# StarMarkDesktop 踩坑记录

> 汇总本项目（**WinUI 3 / .NET 9 / SQLite FTS5 桌面书签管理**）从立项到「桌面组件 + 全局快捷键 + 设置页」体系落地全过程踩过的坑。
> 每条尽量包含 **现象 / 根因 / 修复 / 相关文件**，便于后来者快速排雷。
> 配套文档：[README.md](../README.md) · [项目开发技术文档.md](./项目开发技术文档.md) · [开发进度报告.md](./开发进度报告.md)

---

## 一、构建与工具链

1. **必须显式 `-p:Platform=x64`**
   - 现象：`dotnet build` 默认 `AnyCPU` 触发 `WindowsAppSDKSelfContained requires a supported Windows architecture`。
   - 根因：Windows App SDK Self-Contained 部署要求显式架构；`<Platforms>x64</Platforms>` 只是声明支持列表，不设置默认值。
   - 修复：统一用 `dotnet build StarMark.sln -p:Platform=x64`（测试同理）。`StarMark.UI.csproj` 已做 Platform 归一化（空/AnyCPU/Any CPU → x64）。

2. **WPF → WinUI 3 迁移「XamlCompiler 静默崩溃」真因**
   - 现象：早期误判「WinUI 3 工具链损坏」，改用 WPF 临时替代。
   - 根因：真实是 **C# 编译错误**（`LaunchEventArgs` 拼错）阻塞本地程序集生成，导致 `MarkupCompilePass2` 找不到 `LocalAssembly` → `WMC9999: 未将对象引用设置到对象的实例`。
   - 结论：WinUI 3 工具链完全可用；**任何 C# 错误都会级联成 XAML 编译失败**，先修 C# 再谈 XAML。

3. **WinUI XAML "unknown type" 级联报错**
   - 现象：某条 C# 错误会让整个 UI 程序集生成失败，引发项目内所有 XAML 类型报 `WMC0001 / unknown type` 级联错误。
   - 根因：代码隐藏 `.cs` 编译错误 → 本地程序集缺失 → XamlCompiler 解析不到类型。
   - 修复：**先修 C# 错误**，XAML 错误往往随之消失；不要被海量 XAML 报错误导。

4. **`--disable-build-servers` 避免 MSB3027**
   - 现象：反复构建偶发 `MSB3027: 无法将 DLL 复制到... 正被另一进程使用`。
   - 根因：构建服务器（Roslyn / 热重载）占用输出 DLL。
   - 修复：CI 与本地构建统一加 `--disable-build-servers`。

5. **sln 平台归一（x64-only）**
   - 现象：`dotnet sln add` 会重建出 `Any CPU` 平台，触发 WinAppSDK(SelfContained) 编译失败。
   - 修复：保持解决方案仅 `Debug|x64` / `Release|x64`；`StarMark.Tests` 以同风格加入 sln。

6. **本机 bash shim 缺 coreutils**
   - 现象：Git Bash 环境下 `ls / rm / tail / grep / head` 报 `command not found`。
   - 修复：删文件用 PowerShell `Remove-Item`；Glob 偶发返回陈旧索引（删后仍以「No files found」误报），以 Grep 复核为准。

## 二、XAML / WinUI 渲染陷阱

7. **`x:Bind` 默认 `OneTime` 是 UI 不刷新的头号根因**
   - 现象：运行时修改 VM 属性（空态提示 / 结果列表 / 标签选中态 / 录制按钮文字）全部不刷新；「搜索不清空」「录制按钮文字不变」均由此而来。
   - 根因：WinUI `x:Bind` 默认 `Mode=OneTime`，不订阅 `PropertyChanged`。
   - 修复：所有动态绑定补 `Mode=OneWay`（页面 / 卡片 / 设置页录制按钮 `Content="{x:Bind BindingText, Mode=OneWay}"`）。

8. **`x:Bind x:DataType` 数据模型属性不能是 init-only**
   - 现象：`XamlTypeInfo.g.cs` 对绑定属性赋值报 `CS8852`。
   - 修复：需要被 XAML 绑定的模型属性必须给 setter（不能用 `init`）。

9. **`ItemsRepeater` 内 `{Binding}` 不给条目设 DataContext**
   - 现象：卡片标签芯片 `Tag="{Binding}"` 解析到卡片 VM → `btn.Tag is string` 永远 false → 芯片点击筛选 / ✕ 移除全部静默无效。
   - 修复：改用 `x:Bind`（`Tag="{x:Bind}"` / `Foreground="{x:Bind Converter=...}"`）。

10. **标签云 `UniformGridLayout MaximumRowsOrColumns="0"` 卡死崩溃**
    - 现象：进入「标签」页必崩 / 卡死。
    - 根因：无限网格度量导致布局引擎死循环（误诊为 UniformGridLayout 归零，真正根因见下条）。
    - 修复：固定列数（如 4 列）；崩溃真因其实是根目录 Grid 引用了不存在的画笔（见第 11 条）。

11. **根 Grid 引用不存在的画笔 → `XamlParseException`**
    - 现象：每次进标签页必崩。
    - 根因：`TagsPage.xaml` 根 Grid 引用未定义的 `AppBackgroundBrush`。
    - 修复：改为 `ApplicationPageBackgroundThemeBrush`（统一引用 WinUI 默认主题资源）。

12. **冻结的应用级主题导致浅色白字**
    - 现象：浅色模式下文件夹计数 / 标签区文字 / “全部”按钮发白不可读。
    - 根因：应用级 `Application.Current.RequestedTheme` 在首个窗口创建后即冻结、运行期不可改；运行期切换只改窗口根元素，所有走应用级资源的画笔跟随冻结主题。代码里解析出近白色。
    - 修复：新增 `Helpers/ThemeBrush` 按目标元素 `ActualTheme` 从 ThemeDictionaries 解析；显式双主题调色板（`AppAccentBrush` 等）；`ThemeManager.IsAppDark()` 改读窗口根 `ActualTheme`。

13. **沉浸式标题栏拖拽区吞掉按钮点击**
    - 现象：同步 / 主题 / 设置按钮点不动。
    - 根因：整块按钮列被划进 `SetDragRectangles`（拖拽区过宽）。
    - 修复：拖拽区在按钮列之前收尾，按钮恢复可点。

14. **录制按钮「变扁」**
    - 现象：点击「未设置」按钮清空文字后，按钮纵向塌缩成细横条。
    - 根因：按钮只设了 `MinWidth` 没有高度约束，内容为空 → 高度塌陷。
    - 修复：补 `MinHeight="32"`（与默认按钮同高），清空文字时形状/样式恒定。

## 三、数据层与 JSON 持久化

15. **`System.Text.Json` 默认编码器转义 CJK**
    - 现象：JSON 里中文变成 `\uXXXX`。
    - 修复：备份 / 可读 JSON 用 `JavaScriptEncoder.UnsafeRelaxedJsonEscaping`；篡改检测测试据此设计。

16. **`readonly record struct` 不能被 STJ 回填（配置像被吞）**
    - 现象：组合键只落得单键、配置字段看似没保存。
    - 根因：struct 一定有默认无参构造，STJ 走它；而 `readonly record struct` 的属性只读 → 永远停在默认值。
    - 修复：**凡要 JSON 持久化的值模型一律用可变 `sealed class`（get/set）**，别用 `readonly record struct`。

17. **`WidgetStorage.Load()` / `SettingsStore.Load()` 每次返回新对象**
    - 现象：管理器改 `data.Instances[i].X` 不反映到组件窗口缓存的 `_config`，套用布局时窗口位置不更新。
    - 根因：反序列化每次 new。
    - 修复：显式下发（如 `w.ApplyBounds(x,y,w,h,topmost)`）再 UI 应用。

18. **可空设置字段禁止 `?? default` + `.Value`（崩溃事故）**
    - 现象：旧 `settings.json` 缺新字段，`Enum.IsDefined(typeof(K), d.X ?? 0) ? (K)d.X!.Value : def` 对 null 取值，抛 `InvalidOperationException: Nullable object must have a value`（表现为点设置/全部显示按钮卡死崩溃）。
    - 修复：先 `d.X is { } raw && Enum.IsDefined(raw)` 再取值；新增字段向后兼容要兜底。同模式在 `SettingsStore.LoadWidgetBackdrop()` 等地 5 处加固。

19. **`System.Text.Json` 命名空间细分**
    - `JsonElement` / `JsonDocument` / `JsonSerializer` 在 `System.Text.Json`；`JsonNode` / `JsonObject` / `JsonValue` 在 `System.Text.Json.Nodes`（需额外 `using`）。`JsonValue.Create(...)` 不能赋给 `JsonElement` 字典，改写 JSON 用 `JsonNode` DOM。

20. **同文件并行多次 Edit 丢改**
    - 现象：同一 `.cs` 在同一条消息里既加字段又改方法，字段那次静默丢失、构建才暴露。
    - 修复：同一文件多次编辑必须串行并在改后用 Grep/Read 复核。

## 四、桌面组件窗口与 Win32

21. **8 向缩放 grip：`sealed` 基类 + `ProtectedCursor` 限制**
    - 现象：想派生 `Border/Grid/Canvas/StackPanel` 作 grip 基类失败；在派生类里改光标编译不过。
    - 根因：这些类型均 **sealed**；`UIElement.ProtectedCursor` 是 **protected** 且 WinUI 3 **无** `OnPointerEntered`/`OnPointerExited` 虚方法（与 WPF 不同）。
    - 修复：用 `Panel`（abstract、非 sealed）作基类；在构造函数订阅自身 `PointerEntered`/`PointerExited` 事件设置光标，不可 override。grip 加到根 `Grid`，`Grid.SetRowSpan(grip,2)` + `Canvas.SetZIndex(grip,100)` 压在标题栏/内容区之上。

22. **标题栏按钮与缩放 grip 层级**
    - 现象：grip 区域下按钮点不到；或按钮提升到父 DragBar 仍压不过 grip。
    - 根因：子元素不能越过父级 z 顺序压过叔级 grip。
    - 修复：grip 统一 `ZIndex=100`；需按钮可点则把按钮簇移出 DragBar 作根 Grid 兄弟并设 `Canvas.ZIndex=200`（**提升按钮本身，而非其父**）。

23. **DIP 客户区坐标与 AppWindow 物理像素混用 → 拖动/吸附失效**
    - 现象：组件拖动漂移、边缘吸附不生效。
    - 根因：XAML 用 DIP，AppWindow 用物理像素，两套坐标混算。
    - 修复：全部改为 Win32 `GetCursorPos` 物理像素 + 起始窗口矩形 + 增量；吸附算法用纯函数 `WidgetSnapping`（移植 DeskBox `WidgetSnapCalculator`）。

24. **亚克力材质照搬 DeskBox 控制器方案**
    - 现象：早期 `DesktopAcrylicBackdrop` 直接套用效果不符预期（重叠/不透明/色偏）。
    - 修复：`DesktopAcrylicController` / `MicaController` 挂 `ICompositionSupportsSystemBackdrop`（命名空间 `Microsoft.UI.Composition`，非 `.SystemBackdrops`）；`DWMWA_SYSTEMBACKDROP_TYPE=None` 关 DWM 自带背景；**内容背景透明**让霜化透出；`ConditionalWeakTable<Window,State>` 跟踪 Dispose 旧控制器。Tint 参数用纯数学 `WidgetMaterialVisualCalculator` 照搬 DeskBox。

25. **组件窗口主题不实时换肤**
    - 设计取舍：组件窗口不随主题切换实时换肤，下次显示时读取最新主题（避免每窗挂主题监听）。

26. **DWM 圆角 + `WS_EX_TOOLWINDOW` 无边框序列**
    - 完整复刻 DeskBox `ConfigureWindowCore`：`OverlappedPresenter.SetBorderAndTitleBar(false,false)` + GWL_STYLE 清位 + `DwmSetWindowAttribute` 33/`DWMWCP_ROUND` 圆角 + `SWP_FRAMECHANGED`，不进任务栏 / Alt-Tab。

## 五、全局快捷键与输入

27. **WinUI 3 录制组合键 `Page.KeyDown` 不可靠**
    - 现象：焦点在 TabView / 子控件时，按键未必冒泡到 Page，录制捕获不到。
    - 修复：仿 DeskBox —— 把 `KeyDown` 挂到**被点击的录制按钮本身**，点击录制后 `btn.Focus(Programmatic)` 让按钮留住焦点，按键直接落在按钮上。

28. **修饰键读取方式**
    - 推荐：`InputKeyboardSource.GetKeyStateForCurrentThread(VirtualKey.X).HasFlag(CoreVirtualKeyStates.Down)`（贴合 UI 线程），优于 `GetAsyncKeyState` P/Invoke。

29. **录制期必须挂起 OS 全局热键（连锁触发事故）**
    - 现象：重录「隐藏主界面」按键时，命中旧绑定当场触发隐藏。
    - 修复：`HotkeyService.Suspend()/Resume()` 在 `BeginRecording`/`StopRecording` 调用，录制期注销 OS 热键、保留 `_lastBindings`，结束再重注册。

30. **OEM 标点键显示为十进制（190 / 191）**
    - 现象：部分按键显示成数字而非符号。
    - 根因：`FriendlyKeyName` 未覆盖标点键。
    - 修复：用数字字面量补齐 OEM 标点键（`. / [ ] \ ; ' , - = \`` 等）映射。

31. **类内同名属性遮蔽类型 `VirtualKey`**
    - 现象：静态辅助方法写 `VirtualKey.Space` 报 `CS0120`（非静态）。
    - 根因：模型有同名属性 `HotkeyGesture.VirtualKey` 遮蔽类型。
    - 修复：别名 `using SysVirtualKey = Windows.System.VirtualKey;` 或完全限定名。

32. **快捷键交互规则（用户强约束）**
    - 最多录 3 键，满 3 键（须含主键）自动结束；1~2 键需 Esc 确认。
    - 点击「未设置」按钮只清文字、不变样；点击「已设置」按钮重录并清空文字。
    - 录入后**保存才生效**（只写内存 + 置脏标记，不立即注册）；恢复默认需确认弹窗。
    - 点已设按钮后直接按 Esc 退出录制 = 清除该快捷键。

## 六、MVVM / 绑定刷新

33. **单例 VM 残留旧状态（切走切回闪烁）**
    - 现象：清空搜索后闪现旧结果；标签筛选态丢失。
    - 修复：`SearchPageViewModel` 单例保留查询词 + 结果跨页面；删除自动重搜，仅由搜索框输入触发；数据变化自动刷新。

34. **页面离开必须退订事件**
    - 现象：单例 VM 在 ctor 订阅 `RootsReady` / 全局事件，页面 `OnNavigatedFrom` 不退订 → 死页持续接收重建事件（泄漏 + 崩溃）。
    - 修复：`OnNavigatedFrom` 中 `ViewModel.RootsReady -= handler`；Page 自身订阅的实例事件尤其要注意。

35. **实时刷新（内联改标签后刷新结果）**
    - 机制：`ItemCardActions.ItemTagsChanged` 静态事件（写库后 UI 线程触发），搜索 / 文件夹 VM 订阅并按 `Main.CurrentPageTag` 判断激活页后重跑（`SearchPageViewModel` / `FolderTreePageViewModel` 单例，订阅一次不泄漏）。

## 七、性能 / 卡顿 / 崩溃

36. **`ItemsRepeater` 子项按钮 `Click` 同步移除项 → 崩**
    - 现象：在按钮 `Click` 里同步从它的 `ObservableCollection` 移除该项会崩（被点元素仍在视觉树测量中；移除最后一个标签还会折叠父 Border）。
    - 修复：`DispatcherQueue.GetForCurrentThread()?.TryEnqueue(() => ...)` 延迟到消息队列末尾。

37. **FolderTreePage 手风琴手动建树的三大坑**
    - (1) `LoadAsync` 必须串行化：导航 / 标签变更 / 排序 / 来源 / 隐藏 / 实时改标签均会触发，并发 `Roots.Clear/Add` 竞态 + `RebuildTree` 重入重建会卡死；用 `_loadGate/_loadRunning/_loadPending` 合并并发。
    - (2) 高频事件（如连续改标签）用 `Timer` 去抖（250ms）合并为一次重载。
    - (3) 展开文件夹 / 「展开更多」的卡片与子文件夹构建属重活，必须 `DispatcherQueue.TryEnqueue` 延后到下一消息帧，让点击立即返回、动画先呈现。
    - (4) 非虚拟化手动建树（ItemsRepeater / StackPanel 都不虚拟化）数据量大时需考虑 `RebuildTree` 分批或虚拟化。

38. **窗口 / 页面构造函数读取必须兜底**
    - 现象：异常冒出 Window/Page 构造函数 = XAML 导航失败或直接 UI 线程未处理异常（点按钮后卡死崩溃）。
    - 修复：`WidgetManager.ShowInternal` / `WidgetWindow.ApplyAppearanceCore` / `SettingsPage.LoadFromStoreSilently` 整体 try/catch；排查入口 `%LOCALAPPDATA%\StarMark\logs\starmark-YYYYMMDD.log`。

39. **切换布局后「显示/隐藏组件」变回另一套布局**
    - 现象：快捷键切到布局 B → 隐藏再显示组件，暴露被 B 排除的实例，像「变回了另一套布局」。
    - 根因：「显示」分支原 `foreach ShowInternal(inst.Id)` 显示全部实例；而切换布局只显子集、隐藏其余（不删除）。
    - 修复：`ShowByDefaultLayoutOrAll()` —— 有 `DefaultLayoutId` 则恢复到该布局子集并重新隐藏布局外实例；否则才显示全部（向后兼容）。`ToggleAllInstancesAsync` 与 `ToggleAllAsync` 的显示分支统一改用它。

## 八、架构与领域约定

40. **循环依赖红线：`Core → Data`**
    - 现象：`Core/Language` 被 `Data` 引用时报 `CS0234`。
    - 根因：需被 `StarMark.Data` 使用的逻辑不能放 `Core`。
    - 修复：下沉到 `StarMark.Abstractions`（基础层，无向上引用）；本次把语言逻辑从 `Core/Language` 迁到 `Abstractions/Language`。

41. **标签筛选单一真源**
    - 全局标签筛选单一真源 = `MainViewModel.GlobalTagFilters`（`ObservableCollection<TagFilterChip>`，AND 语义），事件 `GlobalTagFiltersChanged`。
    - 导航栏「标签」(TagsPage) 是**纯选择区域**（标签云多选 → `Main.ToggleGlobalTagFilter`），不内联展示结果。
    - 搜索页 / 文件夹页顶部筛选条绑定 `Main.GlobalTagFilters`，不在两页另开第二套标签入口（历史教训：脱节）。

42. **「语言」下拉 = 编程语言，不是人类自然语言**
    - 语义是按条目的编程语言筛选 GitHub Star（过滤 `extra_json.Language`，由 GitHub API `repo.Language` 写入）。`LanguageCatalog` / `LanguageDetector` 只收录/识别编程语言（Python/Go/…），绝不推断中文/English 之类人类语言，否则污染筛选。

43. **数据完整性：同步不覆盖用户状态**
    - `UpsertOne` 曾经清空笔记、复位隐藏/置顶；改为合并式（Upsert 前读旧值合并 `hidden/pinned/notes`），标签同步从「清空重建」改「合并」，用户标签不再因同步丢失。

## 十、组件扩展与近期迭代新增坑（2026-09-18 · 差异化四格 + 重构整改）

47. **新增组件类型必须「三处同步注册」，缺任一静默失效**
   - 现象：新增 `WidgetKind`（如差异化四格 TagGrid/SearchResults/Activity/Pinned）后，有的不出现在「创建组件」列表，有的点开后内容区空白崩溃。

59. **外观编辑器（纯 C# 构建 UI）的四处 WinUI 3 API 误用（B-9 首编 32 错 30 警根因）**
   - 现象：用代码（`new Button()` 等）拼装 `WidgetAppearanceEditor` 浮层与改 `WidgetWindow.ApplyAppearanceCore` 时，一次性爆出 32 错 30 警，XAML 跟着 `WMC0001/1509/9999` 级联（坑 #49 同型）。逐个修 C# 后复建 0 错 0 警。
   - 根因与修复（四错同源：WinUI 3 控件 API 与 WPF 直觉不同）：
     1. **`Border` 没有 `Foreground` / `ForegroundProperty`**（`CS1061`/`CS0103`）——WinUI 3 的 `Border` 不承载文本前景，想让内容文本变色须用**可继承**的 `Microsoft.UI.Xaml.Documents.TextElement.ForegroundProperty`。**但严禁在 `Border` 上调用该属性的 `SetValue`/`ClearValue`**（见坑 #60：对 Border 调它无论设值还是清除都触发原生 AccessViolation 直接崩）；正确做法是在**内容 Panel（如 `ContentHost` StackPanel）**上 `SetValue` 并延迟到 `Loaded` 之后执行。
     2. **`RenderTransform` 找不到**（`CS0103`）——`RenderTransformProperty` 是 `UIElement` 的静态字段，须用 `UIElement.RenderTransformProperty`（而非无前缀或 `FrameworkElement.`）；文本缩放用 `new ScaleTransform(){ScaleX=ScaleY=...}` 赋给 `RenderTransform`。
     3. **`Window` 无 `KeyDown` 事件**（`CS1061`）——WinUI 3 的 `Window` 不暴露 `KeyDown`；Esc 处理须挂到根可视元素（如编辑器的根 `Panel.KeyDown`），或在 `Window` 上订阅 `Activated`+`KeyDown` 改用 `Microsoft.UI.Xaml.Input` 的键盘事件。
     4. **`ToolTipService.ToolTip = name` 非可设初始化项**（`CS0117`/`CS0747`）——`ToolTipService.ToolTip` 是附加属性，不能当字段赋值；须 `ToolTipService.SetToolTip(btn, name)`。
   - 结论：纯代码拼 UI 时，所有 WPF 习惯的 `X.Foreground` / `X.KeyDown` / 附加属性 `=` 赋值都要按 WinUI 3 的 `TextElement.ForegroundProperty` / 元素级键盘事件 / `SetToolTip` 改写；先 grep `error CS` 修 C#，XAML 级联自然消失。

60. **致命坑：任何"非 TextElement 容器"（Border / Panel / StackPanel 等）上 `SetValue`/`ClearValue(TextElement.ForegroundProperty)` 均触发原生 AccessViolation（0xc0000005，进程崩溃）**
   - 现象：启动即崩溃，WER 报告 `APPCRASH / Exception Code 0xc0000005`，首帧 `ABI.Microsoft.UI.Xaml.IDependencyObjectMethods.SetValue`（或 `.ClearValue`）→ `WidgetWindow.ApplyAppearanceCore` → `ApplyForeground`；栈顶 `WidgetWindow..ctor` ← `WidgetManager.RestoreOnStartupAsync`（恢复已保存组件时撞上）。日志只多一条「内存门禁启动失败」（B-8 的 DI 注册缺陷、被 catch 吞掉、与崩溃无关，别被误导）。
   - 根因：`TextElement.ForegroundProperty` 是 **TextElement** 注册的**附加**属性，**只有真正的 TextElement 子类（如 `TextBlock`）才能安全承载**——其 `Foreground` setter 是标准安全 API。对 **任何"非 TextElement"容器**（无论 `Border`、`Panel` 还是 `StackPanel`）直接调用该属性的 `SetValue` **或** `ClearValue`，WinUI 3 原生层都会越界解引用 → **AccessViolation（Corrupted-State 异常，逃过 `try/catch(Exception)`，直接杀进程）**。本坑**三次**中招：① 初版 `RootBorder.ClearValue`（崩）→ ② 误以为改 `ContentHost(StackPanel).SetValue` + 延迟到 `Loaded` 就安全（**仍崩**，WER 首帧变 `ApplyForeground`→`SetFg`→`SetValue`）→ ③ 才确认"只要在非 TextElement 容器上直接碰该附加属性，无论 Set/Clear、无论 Border 还是 Panel、是否延迟 `Loaded` 都 AV"。WINUI 3 里 `Panel` 同样不"正常支持"这个 TextElement 附加属性（此前"Panel 支持"的判断是错的）。
   - **正确修复**：
     1. **绝不在 `Border` / `Panel` / `StackPanel` 等容器上调用 `TextElement.ForegroundProperty` 的 `SetValue`/`ClearValue`**（任何形态都不行）。
     2. **无显式前景色覆盖时**：直接跳过，让文本沿用主题默认前景（`Application` 资源自带的 `TextFillColorPrimaryBrush`），**完全不碰该附加属性**——这是最稳的默认路径。
     3. **有每实例前景色覆盖时**：安全遍历 `ContentHost` 可视树（`VisualTreeHelper.GetChildrenCount/GetChild` 递归），**只对 `TextBlock`（TextElement 子类）经其标准 `TextBlock.Foreground = brush` setter 上色**；绝不在容器上碰 `TextElement.ForegroundProperty`。`ItemsRepeater` 等虚拟化内容未 realized 的项暂不上色（可接受）。
     4. 整段逻辑包 `try/catch`，且延迟到 `Loaded` 之后执行（确保子元素已生成；但"延迟"本身并不能消除 AV——真正的解法是"不在容器上 SetValue"）。
   - **对照安全项**：`ContentHost.ClearValue(UIElement.RenderTransformProperty)` 安全（`RenderTransformProperty` 由 `UIElement` 拥有，`ContentHost` 本是 `UIElement`）；`Border` 自身的 `Background/BorderBrush/BorderThickness/CornerRadius` 也都是其自有属性，安全。`TextBlock.Foreground = brush` 安全（`TextBlock` 是 `TextElement`）。
   - **排查套路**：启动崩且日志只有 DI/无关 ERROR 时，直接 `Get-WinEvent -FilterHashtable @{LogName='Application'}` 抓 `.NET Runtime` 的 `Stack:`，真实栈首帧会指向 `IDependencyObjectMethods.SetValue`/`ClearValue`；凡是"对非拥有/非承载类型调某附加属性"都优先怀疑。CSE（Corrupted-State）异常普通 catch 捕获不到，只能从 WER 拿栈。

61. **`StackPanel` 以无限高度度量子元素 → 包在里面的 `ScrollViewer` 永不滚动、底部按钮被裁**
   - 现象：给外观编辑器加了「可拖拽标题栏」后，界面无法滚动，「确定 / 取消 / 恢复全局」按钮被遮挡点不到。
   - 根因：把 `dragHeader + scroll` 一起塞进 `StackPanel`。`StackPanel` 在纵向以**无限可用高度**度量子元素，`ScrollViewer` 因此永远拿到「内容有多高就给多高」的测量结果，自身高度不受限 → **滚动条永不出现**，超出窗口的部分被裁掉。
   - 修复：让容器（`Border` 卡片）**直接承载 `ScrollViewer`**（不套 `StackPanel`），`ScrollViewer` 才有有界高度并正常滚动。
   - 结论：凡是要滚动的区域，外层不能是 `StackPanel`；用 `Grid` 分行（内容行 `*`、`ScrollViewer` 放行内）或直接让有界容器承载。
   - 顺带：改为整窗拖拽后，按下点落在 `Button`/`Slider`/`ComboBox`/取色板等输入控件时要放行不劫持指针，并单独排除 `ScrollBar`/`Thumb`（`Microsoft.UI.Xaml.Controls.Primitives`），否则滚动条拖不动。

62. **构造顺序陷阱：`BuildContent()` 晚于 `ApplyAppearanceCore()`，而 `ContentHost` 已 Loaded → 内容永远拿不到已保存外观**
   - 现象：组件文本缩放「恢复全局」后回不到初始加载时的字号；持久化过的外观在重启后对新内容不生效。
   - 根因：构造函数顺序是 `InitializeComponent()` → `ApplyAppearanceCore()` → `BuildContent()`。`ApplyAppearanceCore` 里对内容上色的分支判断 `ContentHost.IsLoaded`：而 `ContentHost` 是 XAML 里**已存在的空 `StackPanel`**，此刻 `IsLoaded` 已为 `true` → 立即执行，却遍历到**空树**（内容还没生成）；又因为是 `true`，`Loaded` 事件的兜底分支**也不会再走**。于是内容在之后被创建出来时，既没被上色、也没被记录基准字号。
   - 修复：`BuildContent()` 之后**清空基准字号缓存并补套一次外观**，保证基准是「未经缩放的原始字号」，恢复全局（系数 1.0）能精确还原。
   - 结论：「延后到 `Loaded`」这类兜底**必须同时判内容是否已生成**，不能只判容器 `IsLoaded`——容器加载 ≠ 内容已建。凡是「先套外观、后建内容」的顺序都要补一次重套。

   - 根因：主窗口 `RootFrame` 里承载的每个 `Page` 根节点都刷了不透明 `ApplicationPageBackgroundThemeBrush`，把窗口级材质**整块盖住**。只把设置页改透明是不够的——切到其它页依旧被盖，且在设置页调滑块时看到的是「本页背景」而非主窗口材质。
   - 修复：把**所有**导航页（文件夹 / 标签 / 搜索 / 动态 / 隐藏 / 设置）根节点设为 `Transparent`，统一由主窗口 `RootGrid` 透出材质。
   - 补充：`MenuFlyout`（右键菜单）是**独立弹出层**，拿不到主窗口的 `SystemBackdrop`，只能用画笔模拟观感一致——在 `App.xaml` 加全局 `MenuFlyoutPresenter` 样式套同一套亚克力画笔。这是 WinUI 弹层的固有限制，无法真正接入窗口材质。

64. **WinRT 异步类型坑：`IAsyncOperation<bool>` 不能隐式转成 `Task<bool>`（CS0266）**
   - 现象：`private async Task<bool> TryControlAsync(Func<Session, Task<bool>> action)` 里传 `s => s.TrySkipNextAsync()` 报 CS0266 + CS1662（lambda 返回类型无法转换）。
   - 根因：SMTC（`Windows.Media.Control`）是 WinRT API，`TrySkipNextAsync` / `TryPlayAsync` / `TryPauseAsync` 返回的是 `Windows.Foundation.IAsyncOperation<bool>` 而非 `Task<bool>`，二者**没有隐式转换**。
   - 关键区分：**`await` 两者都可以**（编译器对 WinRT async 有内建支持），所以方法体里 `await session.TryPlayAsync()` 一直没问题；但**作为委托/方法的返回类型**就必须写 WinRT 类型。把 `Func` 参数改成 `Func<Session, IAsyncOperation<bool>>` 即可。
   - 结论：凡是「把 WinRT 异步方法当 lambda 返回值传出去」的写法都会撞这个错；改成直接 `await`、或把委托类型声明为 `IAsyncOperation<T>`。

65. **拼 URL 时 `double.ToString()` 受区域文化影响：德/法区域会把小数点写成逗号 → 服务端解析失败**
   - 现象：天气组件查询经纬度，在 `de-DE`（及 `fr-FR` 等）区域下拼出 `latitude=39,9042`，Open-Meteo 直接解析失败（表现为「天气一直拿不到数据」）。
   - 根因：`double.ToString()` 默认走 `CurrentCulture` 的 `NumberDecimalSeparator`，德语等区域是逗号。写测试时机器是 `zh-CN`，怎么跑都是点号，属于**只在特定区域复现**的隐性 bug。
   - 修复：拼串统一 `latitude.ToString("G", CultureInfo.InvariantCulture)`。
   - 防护：补一条测试**临时把 `CultureInfo.CurrentCulture` 切成 `de-DE`** 再断言 URL 里是点号而非逗号（finally 里恢复）。凡是要拼进 URL / 协议串 / 文件名的数字、日期，都要按这个套路加区域钉子。

66. **`TextBlockButtonStyle` 等主题资源在部分 WinUI 版本下解析不到 → `StaticResource` 缺失会直接抛异常**
   - 现象/风险：想让按钮「看起来像文本链接」时习惯写 `Style="{StaticResource TextBlockButtonStyle}"`，但该资源并非所有 WinUI 3 版本都提供；`StaticResource` 找不到会在 XAML 解析期直接抛，组件窗口创建即崩。
   - 规避：改成手动压平按钮外观——`Padding="0" BorderThickness="0" Background="Transparent"`，零资源依赖。
   - 结论：组件里尽量少依赖「可能不存在的命名资源」；不确定时宁可手写属性。

67. **SMTC 会话不能以 AUMID 当唯一键：同一播放器多会话会撞车**
   - 现象：想把「音源下拉」的每项用 `session.SourceAppUserModelId` 做标识，两个 Chrome 窗口会合成同一项，选了 A 实际切到 B。
   - 根因：SMTC 的 `SourceAppUserModelId` 只标识**应用**，不标识**会话**；一个应用可以并行多个会话。
   - 修复：会话 id = `AUMID + '\u001F' + 同名序号`（序号由枚举时对同一 AUMID 计数得到），分隔符用不可见控制字符避免与应用名里的字符撞车（DeskBox `MusicSessionService.CreateSessionId` 同法）。同时展示名要走「同名加序号」（`DisambiguateSourceDisplayNames`），否则两个「Google Chrome」用户也分不清。

68. **枚举 WinRT 会话时逐项 try：会话可在枚举与读状态之间消失**
   - 现象：播放器退出瞬间刷新音源列表，`GetPlaybackInfo()` 抛 COM 异常；不接住会冒到 UI 线程。
   - 根因：`GetSessions()` 返回的是一个快照，读每一项的属性时它会重新跨进程求值，中间会话可能已销毁。
   - 修复：`EnumerateSessionEntries` / 读 playback 时逐项 `try`，跳过失效项并记日志；少一条音源远好过崩 UI。同理，用户手选的音源若随播放器退出消失，要**自动回落「跟随系统」**，否则组件会一直显示空占位。

69. **`static Grid`（静态工具方法）里碰实例字段 → `CS0120`**
   - 现象：`BuildForecastRow` 原本是 `private static`，加了单位换算后引用实例字段 `_unit`，编译报 `CS0120: 对象引用对于非静态的字段…「WeatherWidget._unit」是必需的`。
   - 修复：去掉 `static`（它本就只在实例 `Render` 里被调用）。凡是「后来加入对实例状态的依赖」的静态辅助方法，先确认是否真的需要静态；不要为了消除编译错误去加参数传 `_unit`——那会把调用点改坏。

70. **可扩展组件 gatherer 的 XAML 行/列索引要一次改全（`Grid.Row` 残留导致控件消失）**
   - 现象：给天气组件加「今日逐时」横向列表时，新增的 `ScrollViewer` 沿用了旧 **`Grid.Row=2`**，而那一格已被多日预报的 `ScrollViewer` 占用 → 两者叠在同一格，后者被前者的兄弟关系挤到不可见。
   - 根因：给 `RowDefinitions` 追加行但没有同步修正各元素的 `Grid.Row`；XAML 不报错，只是渲染错位。
   - 修复：追加行后把新元素指向新行号（这里是 Row 3），并让「占位提示」用 `Grid.RowSpan` 跨两行；两个视图容器用**一个统一的 `ApplyForecastVisibility(bool empty)`** 计算可见性，避免「切回多日视图时 ScrollViewer 还停在 Collapsed」的状态残留。

71. **`Try<T>(Func<T>, fallback)` 不能拿来包 void 调用**
   - 现象：写 `Try(() => new SettingsStore().SaveWeatherUnit(_unit), _ => { })` 本想「吞掉异常」，实际编译不通过（`Func<T>` 要求有返回值）。
   - 修复：另写一个明确的 `SavePreference(Action<SettingsStore> save)`：`try { save(new SettingsStore()); } catch { log; }`。**写偏好失败只记日志、绝不影响本次渲染**——组件是常驻 UI，保存失败最坏也只是下次启动回到默认值。

72. **SMTC 的 seek 收的是时间轴「绝对」刻度，`Position` 却是相对起点偏移**
   - 现象：给音乐组件加进度拖拽后，在部分播放器上跳到的位置明显不对（总是偏早/偏晚一个固定量）。
   - 根因：`TimelineProperties.Position` 与 `StartTime` 都是时间轴绝对刻度，快照里的 `Position` 是两者相减后的**相对**偏移；而 `TryChangePlaybackPositionAsync(long)` 收的是**绝对**刻度。直接把相对偏移传进去，在 `StartTime != 0` 的会话上就整体偏移。
   - 修复：快照多存一个 `TimelineStartTicks`，seek 时传 `TimelineStartTicks + 目标偏移.Ticks`。换算别用 `(long)TotalMilliseconds * 10_000`（先截断到毫秒再乘，精度白丢），用 `TimeSpan.Ticks` 本身就是 100ns。

73. **拖动进度条期间必须挡掉刷新，否则「拖了又弹回来」**
   - 现象：进度条拖动时每秒一次的刷新会把刚拖到的位置拽回原处。
   - 修复：`SetProgress` 开头加 `if (_seeking) return;`，松手提交后才恢复同步。DeskBox 用同一套 `_isSeeking` 闸门。
   - 配套：**必须 `CapturePointer`，并且同时挂 `PointerReleased` / `PointerCanceled` / `PointerCaptureLost`**。只在控件范围内松手才有 release 事件；拖出组件后松手会丢事件，`_seeking` 永远卡在 true，进度条从此不再更新。

74. **3px 高的 `ProgressBar` 点不中：把指针交给外层容器**
   - 现象：进度条可拖动做出来后，用户反馈"点不准"。
   - 修复：外面套一个 16px 高、`Background="Transparent"` 的 `Grid`（**必须给非 null 背景，否则不参与命中测试**）接管 `PointerPressed/Moved/Released`，`ProgressBar` 本身设 `IsHitTestVisible="False"` 只负责画。
   - 另：拖动过程中**只改文本与条，不要每移动一像素就发一次 seek**，松手才提交，否则会把播放器打爆。

75. **`Grid.Row` 越界不报错，但会把控件甩到布局之外**
   - 现象：天气组件的逐时横向列表"飘"到奇怪的位置（第 70 条改过一次行号，但容器实际只有 0/1 两行，逐时写的还是 `Grid.Row=3`）。
   - 根因：XAML 里 `Grid.Row` 超过 `RowDefinitions` 数量**不会报任何错**，控件被安排到布局之外。
   - 修复：两个视图容器共用同一行（Row=1），靠 `Visibility` 二选一——它们本来就是互斥的，没必要各占一行。改 `RowDefinitions` 后务必逐个核对所有子元素的行/列索引。

76. **给「可拖拽排序」换控件：ItemsRepeater → ListView**
   - 现象：待办要做拖拽排序，`ItemsRepeater` 没有 `CanDragItems` / `CanReorderItems`。
   - 选择：换 `ListView`（`CanReorderItems=True` 会直接调好 `ObservableCollection`，我们只负责持久化），而不是自己接 `DragStarting` / `Drop` 手算插入位置——后者在 ItemsRepeater 上还要处理「UI 线程重入移除集合项会崩」的老问题。
   - 配套：`DragItemsCompleted` 里**不要同步再动集合**，拖放刚结束时框架还在收尾容器状态，同步增删会撞车；走异步（内部 await 后才回 UI 线程改集合）。

77. **SMTC 的回调不在 UI 线程上：所有会话访问与事件通知都必须封送回 UI 线程**
   - 现象：音乐组件的曲目、播放/暂停图标、进度只在**点击按钮**时才更新一次；日志里刷
     `读取媒体会话失败 ... RPC_E_WRONG_THREAD (0x8001010E)`。
   - 根因：`GlobalSystemMediaTransportControlsSession` 是 WinRT 套间亲和对象，`CurrentSessionChanged`
     / `MediaPropertiesChanged` / `TimelinePropertiesChanged` 都在**工作线程**回调。在该线程里读属性
     或去写 `TextBlock.Text` 会直接抛 `RPC_E_WRONG_THREAD`；异常被 `catch` 吞掉后，组件就一直显示上一次的陈旧快照。
     点按钮之所以能刷新，是因为那次调用是从 UI 线程发起的。
   - 修复：`MediaSessionService` 记住构造时的 `DispatcherQueue`，所有公开方法与事件处理器统一走
     `RunOnUiAsync`（`HasThreadAccess` 直通，否则 `TryEnqueue` + `TaskCompletionSource` 回传结果）。
   - 附带：图标「反了」其实是同一个 bug 的表现——UI 拿到的是旧快照，不是字形写错。

78. **进度条不走：快照对象不会自己前进**
   - 现象：进度条数值固定不动，只有点一次播放/暂停才跳一格。
   - 根因：定时器里写的是 `snapshot.Position + 1s`，而 `snapshot` 是**不会自己走**的快照对象，
     每秒都从同一个旧位置加 1 秒，于是永远停在原地。
   - 修复：记住「基准位置 + 读到基准的时刻」，按墙钟推算；每 5 秒回源校正一次（推算会累积误差，
     播放器也可能被系统媒体键改了状态）；推算到头（≥ 时长）立即回源——那通常意味着切歌。
   - 拖动期间用 `_seeking` 闸门挡掉刷新，松手提交前先把基准挪到目标点，否则下一次 tick 会把进度拽回去。

79. **基准字号存在窗口级字典里一定会错位：改记在元素自身的附加属性上**
   - 现象（顽疾）：刚启动组件的字号看着「不是默认」，把文本缩放调回默认后字号反而变大了。
   - 根因：基准记在 `ConditionalWeakTable<TextBlock, object>` 里，「清缓存」与「换内容」这两件事
     没法保证同步；一旦在元素**已被缩放后**重新捕获，基准就变成了缩放后的值，
     此后无论系数是多少都以它为底——于是「调回 1.0」落到的其实是历史缩放值。
   - 修复：新增 `Helpers/WidgetTextScale`，用两个附加属性把「基准字号」与「当初是否显式声明过
     FontSize」记在元素自身（元素随内容一起被丢弃，基准自然一起消失，不可能错位）。
   - 关键细节：系数回到 1.0 时**不能**做乘法，要走精确还原——
     当初显式声明过的写回原值；当初是继承来的必须 `ClearValue` 交还继承链
     （写回一个数值会把继承值钉死，父级再改字号它就永远跟不上）。
   - 配套：滑杆在 1.0 附近 ±0.03 吸附并显示「默认」，否则拇指停在 0.95/1.05 是常态，
     用户会以为「明明调回默认了字还是不对」。

80. **异步/虚拟化建出来的文本拿不到缩放：补一次节流扫描**
   - 现象：同一块组件里字号忽大忽小——天气的指标格、速览的常看按钮是数据回来后才建的，
     列表项容器更是滚动到才创建，首次套用时它们根本不在树上。
   - 修复：`ContentHost.LayoutUpdated` 上挂节流（400ms）补扫；**且只在系数 ≠ 1.0 时扫**——
     默认系数下新文本本就是原始字号，再扫只是在拖动/缩放的布局抖动期白遍历可视树。

81. **WinUI 的滚动条是「覆盖」在内容之上的，不算布局空间**
   - 现象：天气「今日逐时」在组件变窄时，横向滚动条压住每格底部的温度数字。
   - 修复：给滚动内容垫 `Padding`（横向条垫底部 16px，纵向条垫右侧 14px），把它让开。
   - 同类：多日预报的纵向滚动条同样会压住每行右侧的温度，一并垫了右内边距。

82. **数据变更广播：弱订阅 + 订阅方强持有委托 + 去抖，三件套缺一不可**
   - 背景：主界面置顶/删除/改标签后，桌面组件还显示旧数据。收口点在 `ItemRepository` 的每个写方法里
     `DataChangeHub.Notify()`；中枢放 `Abstractions`（依赖方向 `Core → Data → Abstractions`，只有它能被两边引用）。
   - 三个坑：① 静态事件**必须弱引用订阅**，否则关闭的组件窗口连同整棵可视树一起泄漏；
     ② 弱引用的代价是委托会被 GC 立刻回收，所以订阅方（这里是 `DataChangeReloader`）**必须用字段强持有**
     那个 `Action`，否则订阅当场失效；③ **必须去抖**——一次批量写入会连发 N 次通知，
     不去抖就是把同一个列表重载 N 遍，表现为「点一下待办卡几秒」，而且这一路都在 UI 线程上，
     同屏其它组件跟着发呆（用户报的"输一条待办，其它组件鼠标悬浮没内容"）。
   - 另：`DispatcherQueueTimer` 是套间亲和对象，通知可能来自线程池，不能跨线程直接 `Start`，
     要 `TryEnqueue` 回 UI 线程再起表。

83. **`x:Bind` 的 `Converter={StaticResource X}` 忘了在资源字典里声明 → 渲染期 COMException 0x80004005，直接崩进程**
   - 现象：给待办**新增一条**就卡死崩溃；把该组件收成胶囊后**鼠标悬停预览**也崩（预览要让内容重新参与布局）。
     日志里是 `UI 未处理异常: COMException (0x80004005) Cannot find a resource with the given key: TextToVisibility`，
     栈顶在 `TodoWidget_obj10_Bindings.LookupConverter` → `MeasureOverride`。
   - 根因：`TextToVisibilityConverter` 类写在了 `TodoWidget.xaml.cs` 里，但 `TodoWidget.xaml` 的
     `<UserControl.Resources>` 只声明了另外三个转换器，**漏了它**。编译照样过（XAML 编译器不会校验
     编译绑定的资源键），崩溃发生在 DataTemplate 实例化后第一次 Measure 时，
     而这一路在原生布局里，**业务代码的 try/catch 根本包不住**。
   - 修复：补上 `<local:TextToVisibilityConverter x:Key="TextToVisibility"/>`。
   - 通用排查：`x:Bind` 带 Converter 时，**每个 `StaticResource` 键都必须在资源字典里声明**。
     写个小脚本把「用到的键」与「声明的键」求差集最快（排掉 WinUI 内置的 `*Brush` / `*TextBlockStyle` 即可）。
     顺手给 `PeekExpand` 也加了 try/catch 兜底：预览失败要能立刻把胶囊收回去，
     否则 `_peeking` 卡 true，胶囊再也收不回、下次悬停继续炸。

84. **`DispatcherQueueTimer` 默认只走一次：`IsRepeating` 必须显式置 true**
   - 现象：音乐组件的进度条每秒动一下就再也不动（看着像"与实际不符"）。
   - 根因：`_timer.Start()` 只保证它**滴答一次**；DeskBox 里凡是想持续跑的定时器都显式写了
     `IsRepeating = true`（它那两个一次性定时器反而显式写 `false`，容易看反）。
   - 修复：`StartTimer()` 里创建即设 `IsRepeating = true`；并且**有曲目就一直开着**（暂停中也要回源，
     否则用系统媒体键按了播放，组件要等下一个事件才反应，而部分播放器压根不发事件）。

85. **SMTC 的三个精度坑：刷新合并不能「丢弃」、时间轴是旧快照、EndTime 可能缺失**
   - ① 重叠刷新闸门**不能直接 return**：曲目事件与时间轴事件常连发，后者在途时前者被丢掉，
     于是"切了歌组件还显示上一首"。改成置脏位 `_refreshPending`，在途结束后补跑一次。
   - ② `TimelineProperties` 是播放器**上一次上报**的快照（多数 1 秒一次），直接拿 `Position` 画
     永远慢半拍。播放中要按 `LastUpdatedTime` 把到此刻的流逝补回去（只在 0~15s 区间内补，
     防止脏时间戳把进度条拉爆）。
   - ③ 部分播放器（尤其浏览器）不给 `EndTime`（等于 `StartTime`），长度会算成 0、进度条恒为 0%。
     回退到 `MaxSeekTime - MinSeekTime`。
   - 另外：**部分播放器换下一个视频/音频时不发 `MediaPropertiesChanged`**，
     所以除了事件驱动，还必须保留低频轮询（当前 3 秒一次），否则"切歌识别不到"这个现象无解。

86. **材质两个滑杆在「云母」下完全失效：`CalculateMica` 漏了 surfaceOpacity**
   - 现象：材质选云母 / 云母 Alt 时，拖「背景不透明度」对所有组件都没反应（「材质浓度」有反应）。
   - 根因：亚克力走 `tint * Lerp(0.08,1.0,opacity)`，而云母的 `CalculateMica(isDark, useAlt, intensity)`
     压根没接 `surfaceOpacity` 这个参数。
   - 修复：给 `CalculateMica` 补上 `surfaceOpacity`，与亚克力同口径乘表面强度因子。

87. **主窗口的材质不能直接照抄组件：内容是不透明的，霜化根本看不见**
   - 现象：主窗口选「纯色」时**整个窗口全透明**（与 DeskBox 完全不是一个东西）；
     两个滑杆对主界面调了也没变化。
   - 根因有两条：
     ① `RefreshAppearance` 写成「半透明就 `RootGrid.Background = null`」，而纯色 / 实色
        这一路**不挂任何控制器**（DeskBox 里纯色走 `TransparentTintBackdrop` 铺在窗口背景上），
        于是主窗口什么都不铺 = 全透明；
     ② 即便挂上亚克力/云母，顶栏（`LayerFillColorDefaultBrush`）、NavigationView、各页面
        都自带不透明背景，霜化被盖住后无论怎么调滑块都看不出差别。
   - 修复：新增 `WidgetAppearance.MainWindowSurfaceBrush`——
     未开启材质 → 主题实色；纯色 / 实色 → 与组件同一套 `SurfaceBrush`（按不透明度调 Alpha）；
     原生材质 → 在霜化之上压一层**按不透明度调 Alpha 的主题色**，让「背景不透明度」字面生效。
   - 强调色必须取**系统强调色**（`UISettings.GetColorValue(UIColorType.Accent)`），
     不能写死固定蓝：DeskBox 走的是 `ThemeService.GetEffectiveAccentColor()`，写死就是"和 DeskBox 不是一个色"。

88. **材质控制器要复用，不能每次都 Dispose + new**
   - 早先 `ApplyBackdrop` 每次进入都 `DetachControllers`（`RemoveAllSystemBackdropTargets` + `Dispose`），
     再 `new` 一个新的。切换材质是高频操作（设置页滑块是去抖 350ms 实时保存的，拖一次触发几十次），
     反复创建会漏原生合成内存与 DWM 句柄——这类泄漏 **GC 与工作集修剪都收不回来**。
   - 照搬 DeskBox：控制器留在窗口状态里复用，切换材质族时只摘挂载点（`RemoveAllSystemBackdropTargets`），
     `Kind` / `TintColor` / `TintOpacity` 是可变属性，直接改写即可。
   - 代价：必须显式释放——新增 `WidgetAppearance.ReleaseBackdrop(window)`，
     组件窗口 `Closed` 与主窗口 `ExitApp` 各调一次。

89. **原生材质的霜化层透不出来的真因：缺 `DwmExtendFrameIntoClientArea(-1)`（整窗玻璃化）**
   - 现象（第三十一轮）：修完 #86/#87 后，四种原生材质（亚克力薄/厚、云母/云母 Alt）下
     拖「背景不透明度 / 材质浓度」**依然毫无变化**；只有改文字大小（触发一次 `ApplyAppearanceCore`）
     时背景才突然变一下 —— 于是用户推断"滑块的值被攒着，等别的操作才生效"。
   - 根因：DeskBox 在挂控制器之前先调 `Win32Helper.ApplyFullWindowFrame`
     （`DwmExtendFrameIntoClientArea` 四边距全 `-1`），这一步是**霜化层能透出来的前提**。
     StarMark 从没调过：窗口客户区由系统按不透明底色绘制，内容 `Background` 设成透明也只是
     透出那层底色，控制器的 `TintOpacity / LuminosityOpacity` 再怎么改都被盖在底下。
   - 修复：`WindowInterop.ApplyFullWindowFrame / ClearFullWindowFrame` + 沉浸式深色属性
     （`DWMWA_USE_IMMERSIVE_DARK_MODE`，对齐 DeskBox 的 `SetWindowTheme`）；
     原生材质走玻璃化，`None / Solid` 走 `ClearFullWindowFrame`。
   - 教训：抄 DeskBox 的**控制器参数**只是抄了一半，窗口管道同样是不可省略的一半。

90. **原生材质的内容表面不能一律透明：给一层"吃不透明度 + 吃浓度"的表面色兜底**
   - 只靠控制器驱动背景，等于把可见性押在"霜化一定透得出"上（见 #89）。
     新增 `BuildNativeSurfaceColor`：**背景不透明度 → 表面 Alpha**（0.10→0.94，越低越见壁纸），
     **材质浓度 → 染色浓度**（accentMix 0.06→0.40）。
   - 主窗口与组件共用 `SurfaceBrush`（`MainWindowSurfaceBrush` 退化为它的薄封装），
     两套各写一份正是"主界面调了没反应、组件调了才变"的来源。

91. **改文字大小会把背景色改掉：预览回调不该重挂材质**
   - 现象：外观编辑器里拖「文本缩放」滑杆，组件的背景颜色跟着变，"恢复默认"也回不来。
   - 根因：预览回调一律走整块 `ApplyAppearanceCore`（材质 / 背景 / 边框全部重来），
     在材质尚未即时生效时，这一下重挂就是把"攒着的设置"补上 —— 看起来像"字号改了背景"。
   - 修复：`ShowAsync` 增加 `liveTextPreview` 通道，文本缩放只走 `ApplyTextAppearanceCore`
     （前景色 + 字号），不碰材质与背景。
   - 顺带：主窗口 / 组件的外观刷新必须**即时**（设置页滑块 350ms 去抖保存后立刻刷新），
     任何"等下一次重绘才生效"的路径都会让用户以为滑杆坏了。

92. **`CreateRoundRectRgn` 的右/下边界是排他的 —— 组件的右、下边框凭空少 1px**
   - 现象：组件右侧与下侧边框比左、上细，边框粗细 ≤1 时右/下干脆看不见。
   - 根因：`CreateRoundRectRgn(0, 0, w, h, ...)` 生成的区域只覆盖到 `w-1 / h-1`
     （GDI 矩形约定：不包含右/下边）。窗口被自己的圆角区域裁掉一圈，
     恰好等于把右/下边框削掉 1px。
   - 修复：`CreateRoundRectRgn(0, 0, w + 1, h + 1, r, r)`。

93. **SMTC 没有"倍速"字段，按 1× 墙钟推算进度必然失真**
   - 现象：播放器开 1.5× / 2× 时组件进度条越走越慢，越到后面差得越多。
   - 根因：`GlobalSystemMediaTransportControlsSessionTimelineProperties` 只给位置与总长，
     不给 `PlaybackRate`；`tickBase + 墙钟流逝` 隐含假设倍速 = 1.0。
   - 修复：用相邻两次**真实**读数的位移 / 时间差反推倍速（`_rate`，0.25×–8× 之外视为跳变丢弃，
     平滑收敛），推算改为 `tickBase + 流逝 × _rate`；回源从 3 秒一次收紧到 2 秒一次，
     换倍速后两秒内自动跟上。

- #100 **纯色（Solid）材质浅色发灰，且与 DeskBox 不一致**
  - 现象：浅色下纯色材质把主界面与组件背景渲染成灰；StarMark 的纯色不像 DeskBox 那种「半透明着色面板」。

    `Brush(...)` 经 `ThemeBrush.For(EffectiveTheme(), key)` 按用户存储主题解析，浅/深都正确。

- #109 **组件外观编辑器弹窗始终为深色主题**
  - 现象：打开「组件外观」编辑器，无论用户设浅色还是跟随系统，弹窗始终是深色。
  - 根因：① 旧代码在 `win.Content` 还是 null 时就调 `ThemeManager.Apply(win, pref)`（空操作，见 #104）；
    ② 代码侧取色用 `ThemeBrush.For(ElementTheme.Default, key)`，按系统主题而非用户偏好解析。
  - 修复：把 `ThemeManager.Apply(win, pref)` 移到 `win.Content = card` 之后；新增 `EffectiveTheme()` 把
    `SettingsStore.LoadTheme()` 折算成 `ElementTheme`，所有 `Brush(...)` 改用 `ThemeBrush.For(EffectiveTheme(), key)`。

- #110 **设置页内用主界面右上角快捷切主题，退出设置页主题被强制切回旧值**
  - 现象：停留在「设置」页时，点主界面右上角主题按钮切换深浅色，设置页主题选择不同步；退出设置页后主题又被切回旧的。
  - 根因：`MainWindow.ThemeButton_Click` 只更新自身 `_themePref` + 落盘 + 同步组件，不通知 `SettingsPage`；
    设置页 `OnNavigatedFrom` 兜底执行 `SaveCommand`，按其过期的 `ThemeIndex`（仍是旧主题）回写 → 强制切回。
  - 修复：`MainWindow` 新增静态事件 `ThemePreferenceQuickSwitched`（在 `ThemeButton_Click` 末尾触发）；
    `SettingsPage` 在 `OnNavigatedTo` 订阅、`OnNavigatedFrom` 退订；回调 `OnExternalThemeSwitch` 用
    `_suppressSave` 包住把 `ViewModel.ThemeIndex` 同步成新主题（值已由主窗口落盘，不再触发自动保存），
    离开设置页兜底保存写回的就是当前主题，不再强切回。

- #111 **弹窗（所有类型 / 所有主题）背景变成深黑色**（第三十五轮修复的回归）
  - 现象：第三十五轮修复上线后，所有弹窗（确认/输入/提示/通用内容/组件外观编辑器）在所有主题下背景都是深黑色。
  - 根因：① 弹窗背景走代码侧 `ThemeBrush.For(EffectiveTheme(), "CardBackgroundFillColorDefaultBrush")`，
    `EffectiveTheme()` 基于 `SettingsStore.LoadTheme()`（磁盘存储偏好）；运行期主界面切换主题后磁盘偏好并不立即落盘，
    主界面已切浅色、磁盘仍为 `Default`/跟随系统深色时，弹窗按旧偏好渲染成深色，与主界面割裂；
    ② 代码解析主题画刷不如 XAML `{ThemeResource}` 可靠（后者与 `WidgetWindow` 同款机制、生产环境已验证）。
  - 修复：新增 `Views/PopupCard.xaml`（根 Border 背景/边框走 XAML `ThemeResource`，跟随窗口根 `RequestedTheme`）；
    `CenteredDialog.BuildCard` 与 `WidgetAppearanceEditor` 卡片改用 `PopupCard`，不再用代码侧画刷解析卡片背景/边框；
    弹窗主题来源从「磁盘存储偏好」改为「主窗口当前实际主题」——`MainWindow` 暴露 `CurrentThemePreference`，
    `CurrentThemePref()` / `Apply` / `EffectiveTheme()` 统一取 `App.MainWindow?.CurrentThemePreference ?? LoadTheme()`，
    弹窗与主界面视觉主题始终一致。构建遇 WinUI XAML 编译器 `WMC1509`（新增 XAML 触发 Pass2 缓存损坏致本程序集类型
    解析失败），`dotnet clean` 后重建即恢复。
