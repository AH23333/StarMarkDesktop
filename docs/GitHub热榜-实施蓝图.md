## 1. 为什么现在做（以及为什么它曾被漏掉）

1. **这不是新功能，是补齐一次漏抄。** 浏览器扩展 `StarMark` 里热榜已经做完并在用：`src/core/trending.ts` 抓 `github.com/trending/{lang}?since={daily|weekly|monthly}` 的 HTML，正则切 `<article>` 得到 `{fullName, url, description, language, stars, starsToday}`，页面抓取失败自动回退 Search API，并把来源回传给界面标注（`via: 'trending-html' | 'search-api'`）`[读码转述]`。
2. 桌面端 `docs/` 全量 grep `热榜|trending` **零命中**`[已核实]` —— 上一轮"对照扩展补齐差距"时它从未被登记成差距（那份 40 KB 的 `StarMark扩展对比与补齐方案.md` 也没列它）。所以这次的正确姿势是：**先登记差距，再谈实现**。

## 3. 选定架构（推荐：方案 A + 兜底 B）

| 方案 | 做法 | 判定 |
| --- | --- | --- |
| **A（推荐）** | 桌面自己抓 `github.com/trending` HTML + 正则解析，失败回退 `api.github.com/search/repositories`（匿名，60 req/h） | 与扩展同源同形状 ⇒ 可直接借用它已验证的解析口径与兜底语义；零配额消耗、匿名可用（满足 C1）。代价：页面无官方契约，改版会哑 ⇒ 所以 **B 兜底 + 来源标注 + 解析器可单测**是硬性配套 |
| B（兜底，随 A 一起做） | Search API：`created:>N stars:>50&sort=stars`（`PERIOD_DAYS` daily:2 / weekly:7 / monthly:30 `[读码转述]`） | 拿不到 `starsToday`，UI 必须据此降级显示（不能显示"今日 +0"骗人） |
| C（暂不做，登记为 P-68） | 从浏览器扩展导入它已缓存的热榜 | **本轮核实：两个项目之间零运行时通道**——扩展无 HTTP 服务、无 Native Messaging、无协议 handler、落盘只经浏览器下载 API；桌面读的是浏览器书签文件而非扩展数据；两边备份信封标识也不同（`starmark` vs `starmark-desktop`）。要做 C 得先建"扩展↔桌面"通道，那是另一个量级的工程，且与热榜无关 |

**新增一处外网访问要说清楚**：目前全项目只有两个外网出口（GitHub API、Open-Meteo 天气）。热榜是第三个，host 固定 `github.com` / `api.github.com`，**不带任何用户数据、不带 Token**（抓 HTML 那条腿），也不做遥测。

## 4. 核心取舍：热榜条目**默认不进 `items` 表**（P-67）

这是整份设计里唯一会决定后面所有形状的判断，所以单列一节。

- **推荐：独立缓存 + 独立浏览面。** 抓到的候选只存进现成的 `sync_state` 表（`src/StarMark.Data/Schema.sql:136-139`，键如 `trending:<period>|<lang>`，值是 JSON + `fetchedAt`）⇒ **零新表、零迁移**（满足 C7），且天然不进 FTS / 不进统一搜索 / 不进文件夹树 / 不进活动流 / 不进备份（P-72 单独确认这一条是否可接受）。
- 唯一入库入口 = 用户在卡片上主动点 **🔖 书签（＝"收进收藏"）**，此时按现有 upsert 路径写 `items`（**`Type=Bookmark`、本地来源、按规范化 URI 去重，再点可移除**）。⚠ 与原文档不同的一点已按用户裁决改正：**「收进收藏」写的不是 `GitHubStar`**——⭐Star 按钮改的是 **GitHub 远端状态**，它带来的 `GitHubStar` 条目由**下次同步**带回来，两者是两个不同落点（本机收藏 / 远端 star），tooltip 与结果文案必须让用户分得清。
- 顺带一个待核实的后果（**实现到 KD/KF 时验证，不此处下结论**）：同一仓库既被点 Star 又被收进书签 ⇒ 库里会有两行（`Source`/`Type` 不同、URI 相同）。浏览与搜索侧是否按规范化 URI 合并展示，取决于既有的去重/合并口径（R-P1-8 那次做的是搜索结果合并），届时以实测为准并在此更新。
- 反面选项（P-67 的 B）：以 `ItemType.GitHubTrending` 入库 ⇒ 看着"更统一"，但要动 `ItemModel.cs:16-26` 的**钉值枚举**（EV 轮契约：只能追加不能插），并连带 `FolderPathUtil`、`ItemCardViewModel` 图标、`SearchFilter.Type` 分派、备份与迁移全部重新过一遍——正是历史上"加一个可见条目类型＝立刻制造静默死菜单项"那条教训的复发场景。除非你明确要"热榜也进统一搜索"，我不建议。
- **顺带纠正一处会误导实现者的注释**：`Schema.sql:14` 写着 type 取值是 `'github_star'`，而实现写的是 `Type.ToString().ToLowerInvariant()` ⇒ 真值是 `'githubstar'`（`ItemRepository.cs:603,660`）`[已核实]`。注释不实，我按四闸门 ②③ 直接改注释（不等你拍板，见批次 JH），免得热榜按注释写查询恒空。

## 5. 界面与交互（**已按 2026-09-23 用户裁决改写**）

**落点：导航栏「剪贴板」右侧的「热榜」项**，不是新窗口、不是第 13 种桌面组件。

- 导航项：`MainWindow.xaml:196-200`（剪贴板项）之后加 `NavTrendingItem Content="热榜" Tag="trending"`；`MainWindow.xaml.cs:490-502` 的 tag→页面映射加一行。
- **开关关闭 ⇒ 导航项不显示**（用户明确要求），并且：正停在热榜页时关掉开关要退回文件夹页，不能留一屏空白。入口本身在设置页必须找得到，卡片描述写清"开启后导航栏会出现「热榜」"。
  > 这与剪贴板那次刻意相反（剪贴板入口常驻，因为"藏了等于用户找不到"）：热榜是**用户主动开启的可选浏览面**，关着还留一个点进去只会看到"未开启"的页，更像故障。两种做法各自的理由都记在这里，免得后来人以为是疏忽。
- **复用已有条目卡片** `Controls/ItemCard`（同一视觉、同一批字段），行数据是**外部候选**：`Id = 0`、`Source == ItemSources.Trending`、`Uri = https://github.com/owner/repo`、`Title = fullName`、`Subtitle/Description = 描述`、`StarsCount = 总星数`。
- ⚠ **必须屏蔽一切会写主库的动作**：置顶 / 隐藏 / 编辑笔记 / 编辑标签 / 发送到桌面 / 删除。它们对 `Id = 0` 的候选会经 `EnsureRecordedAsync` 把热榜条目**塞进 items**（＝直接违背 P-67"默认不入库"）。判据做成**一个纯函数** `ItemCardViewModel.ShowsLibraryActions`（＝非启动器模式 且 非热榜候选），`ItemCard.xaml` 里原先逐处写 `IsLauncherMode … ConverterParameter=Invert` 的分派改走它——与 IF 轮"判据下沉成一个纯函数"同口径：**逐个动作判"该不该出现"，而不是指望宿主模板传对模式位**。
- 行内两个图标动作（沿用 `MiniIconButton` 样式，只在热榜候选上出现）：
  | 动作 | 语义与状态机 | 依据 |
  | --- | --- | --- |
  | **⭐ Star** | 未 Star ⇒ `☆ Star`；点 ⇒ `PUT /user/starred/{owner}/{repo}`（204 成功）。已在本地 star 列表 ⇒ `★ 已 Star`；**再点 ⇒ `DELETE`（取消 Star）**。未配 Token ⇒ 不做前置禁用，点完给**明确失败**："Star 失败：未配置 GitHub Token" + 就地「去设置里配 Token」按钮。 | 扩展 `github.ts:120-138`、`TrendingView.tsx:82-89`；**取消 Star 是桌面新增**（扩展 `disabled` 后无路，全仓无 unstar）；"不禁用、事后报错"是扩展既有口径（`App.tsx:399-411`），桌面沿用但把 toast 换成页内状态行 + 真按钮 |
  | **🔖 书签**（＝"收进收藏"） | 写一条本地 `ItemType.Bookmark` 条目（规范化 URI 去重），再点可移除。**与 Star 是两个不同落点**：一个进本机收藏、一个改 GitHub 远端状态——tooltip 与结果文案都要说清，否则用户会以为点了两次同一件事。 | 扩展那边是 `browser.bookmarks.create` 写浏览器书签栏（`App.tsx:413-424`），桌面**没有该通道** ⇒ 落到本地 items |
- **「已 Star」的判定口径**：比对**本地已同步**的 `GitHubStar` 条目（按 `owner/repo`），与扩展同形状（`App.tsx:202-213`），**不发 HEAD 探测** `/user/starred/{owner}/{repo}`。后果必须写进界面而不只是文档：在网页上刚 star 的仓库要到下一次同步才显示"已 Star" ⇒ 该处文案不得出现"实时"字样。
- **筛选与刷新**（与本文档原设计一致）：周期 日 / 周 / 月（默认**周**，同扩展）+ 语言（「全部」+ 我库里的语言 Top8，取自 `InsightsService.cs:100-107`，并可手输其他）。进入页面时"同一本地日历日"命中缓存则不发请求；页内「刷新」强制重抓；抓取失败 ⇒ 回读旧缓存并标 stale + 就地「重试」。**不加任何常驻定时器**（`GitHubOptions.SyncIntervalSeconds` 仍无消费者，热榜不借它塞进第一个自动任务）。
- 四个状态各带下一步：加载中 / 空（"热榜暂无数据"）/ 失败（带原因 + 「重试」）/ stale（"上次结果，N 小时前" + 「重试」）。**空与失败必须能分辨**——把抓取失败显示成空列表，就是让人去查一个不存在的问题。

## 8. 风险与可行性再分析

1. **页面结构会变**（唯一真风险）。缓解：解析失败必须**可见 + 自动兜底 + 回读旧缓存**，且解析器是纯函数 ⇒ 改版时改一个文件、补一条 fixture 用例即可，不会蔓延。这也是我坚持把它放可机检层的原因。
2. **解析外部 HTML 的安全面**：只取"相对路径 `/owner/repo`"重建 `https://github.com/owner/repo`，**绝不直接使用 href 原值**（防 `javascript:`/`data:`/自定义 scheme 混进 `Item.Uri`）；最终打开仍过 `LauncherEx` 白名单。正则只跑在有长度上限的输入上（防放大）。日志不记正文（C6）。
3. **限流**：HTML 腿无配额概念但可能被反爬（返回验证页 ⇒ 解析出 0 条 ⇒ 必须落到"解析失败"分支而不是"今天没有热榜"）；Search API 匿名 60/h，所以兜底也必须**只在需要时用 + 结果同样入缓存**。
4. **不要顺手改的东西**：`GitHubOptions.SyncIntervalSeconds` 无人消费（属既有登记项），热榜不借此引入第一个自动同步定时器；如果哪天真要自动同步，那是单独的决定。
5. **时间戳单位**：扩展全用**毫秒**、桌面 Schema 全用 **Unix 秒**（`Schema.sql:3`）`[读码转述/已核实]`。若将来做方案 C（导入扩展数据）必须显式换算——写在这里是为了不让后来人踩。
6. **`type` 真值与注释不符**：见 §4 末（批次 JH 修）。

## 10. 验收清单（真机 `[v]`，随各批次补全）

① 未配 Token 也能看到热榜（读侧完全不依赖 Token）；② 断网 / 被反爬时页面说的是"抓取失败·已显示上次结果（N 小时前）" + 「重试」，而不是空列表（**空与失败必须分得开**）；③ 设置里关掉热榜开关 ⇒ 导航栏「热榜」项消失，若正停在该页要退回文件夹页；再开启 ⇒ 项回来且不需要重启；④ 热榜卡片上**看不到**置顶 / 隐藏 / 笔记 / 标签 / 发送到桌面这些动作，点 Star 或书签后它们也不该出现在别处（＝默认不入库）；⑤ ⭐Star：未配 Token 时点它要给"Star 失败：未配置 GitHub Token" + 一个能跳到设置里 Token 那一行的按钮；配好后点 ⇒ 按钮转「已 Star」，**再点可取消**；⑥ 🔖书签：点一次进本机收藏（在「文件夹」的书签分组可见），再点可移除，连点两次不产生重复行；⑦ 没点书签的候选不出现在收藏计数 / 语言分布 / 健康度分母 / 统一搜索里；⑧ 切周期或语言时不重复抓同日已缓存的键（日志核对）；⑨ 开启功能时弹出"是否在今日速览显示热榜"，默认日榜；选"是"后组件里热榜在上、原「常看」在下；对组件里的热榜行右键应能看到 Star 与收进收藏两项且都生效。

## 11. 回退方式

功能整体挂在设置页那一个开关后面（P-70 默认关）：不打开 ⇒ 无新请求、无新表、无 schema 变更、`items` 无新来源，且导航栏不出现「热榜」项。批次 **KA/KD 的可机检部分与 KC** 落在纯逻辑/服务层，未接线前不被任何现有路径调用 ⇒ 等于天然可回退；**KE～KH** 是卡片增量、页面、设置卡与 Glance 块的接线，回退＝摘掉导航项、卡片和组件里那块列表。唯一需要留意的不可逆点是"用户主动点了 🔖 书签"所产生的条目——那本来就是用户自己的动作，走既有的删除/隐藏路径即可（同一按钮再点即移除，见 §5）。
