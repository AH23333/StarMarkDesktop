## 1. 为什么现在做（以及为什么它曾被漏掉）

1. **这不是新功能，是补齐一次漏抄。** 浏览器扩展 `StarMark` 里热榜已经做完并在用：`src/core/trending.ts` 抓 `github.com/trending/{lang}?since={daily|weekly|monthly}` 的 HTML，正则切 `<article>` 得到 `{fullName, url, description, language, stars, starsToday}`，页面抓取失败自动回退 Search API，并把来源回传给界面标注（`via: 'trending-html' | 'search-api'`）`[读码转述]`。
2. 桌面端 `docs/` 全量 grep `热榜|trending` **零命中**`[已核实]` —— 上一轮"对照扩展补齐差距"时它从未被登记成差距（那份 40 KB 的 `StarMark扩展对比与补齐方案.md` 也没列它）。所以这次的正确姿势是：**先登记差距，再谈实现**。

## 3. 选定架构（推荐：方案 A + 兜底 B）

| 方案 | 做法 | 判定 |
| --- | --- | --- |
| **A（推荐）** | 桌面自己抓 `github.com/trending` HTML + 正则解析，失败回退 `api.github.com/search/repositories`（匿名，60 req/h） | 与扩展同源同形状 ⇒ 可直接借用它已验证的解析口径与兜底语义；零配额消耗、匿名可用（满足 C1）。代价：页面无官方契约，改版会哑 ⇒ 所以 **B 兜底 + 来源标注 + 解析器可单测**是硬性配套 |
| B（兜底，随 A 一起做） | Search API：`created:>N stars:>50&sort=stars`（`PERIOD_DAYS` daily:2 / weekly:7 / monthly:30 `[读码转述]`） | 拿不到 `starsToday`，UI 必须据此降级显示（不能显示"今日 +0"骗人） |
| C（暂不做，登记为 P-68） | 从浏览器扩展导入它已缓存的热榜 | **本轮核实：两个项目之间零运行时通道**——扩展无 HTTP 服务、无 Native Messaging、无协议 handler、落盘只经浏览器下载 API；桌面读的是浏览器书签文件而非扩展数据；两边备份信封标识也不同（`starmark` vs `starmark-desktop`）。要做 C 得先建"扩展↔桌面"通道，那是另一个量级的工程，且与热榜无关 |

**新增一处外网访问要说清楚**：目前全项目只有两个外网出口（GitHub API、Open-Meteo 天气）。热榜是第三个，host 固定 `github.com` / `api.github.com`，**不带任何用户数据、不带 Token**（抓 HTML 那条腿），也不做遥测。

## 4. 核心取舍：热榜条目**默认不进 `items` 表**（P-67）

这是整份设计里唯一会决定后面所有形状的判断，所以单列一节。

- **推荐：独立缓存 + 独立浏览面。** 抓到的候选只存进现成的 `sync_state` 表（`src/StarMark.Data/Schema.sql:136-139`，键如 `trending:<period>|<lang>`，值是 JSON + `fetchedAt`）⇒ **零新表、零迁移**（满足 C7），且天然不进 FTS / 不进统一搜索 / 不进文件夹树 / 不进活动流 / 不进备份（P-72 单独确认这一条是否可接受）。
- 唯一入库入口 = 用户在卡片上主动点「**收进收藏**」，此时按现有 upsert 路径写 `items`（`Type=GitHubStar, Source=github`），并因此进入他已有的标签 / 置顶 / 隐藏 / 快照 / 备份全链路。**用户点一下才变成收藏**，语义干净，也复用了现成机制（`ItemCardActions` 的 `EnsureRecordedAsync` 家族）。
- 反面选项（P-67 的 B）：以 `ItemType.GitHubTrending` 入库 ⇒ 看着"更统一"，但要动 `ItemModel.cs:16-26` 的**钉值枚举**（EV 轮契约：只能追加不能插），并连带 `FolderPathUtil`、`ItemCardViewModel` 图标、`SearchFilter.Type` 分派、备份与迁移全部重新过一遍——正是历史上"加一个可见条目类型＝立刻制造静默死菜单项"那条教训的复发场景。除非你明确要"热榜也进统一搜索"，我不建议。
- **顺带纠正一处会误导实现者的注释**：`Schema.sql:14` 写着 type 取值是 `'github_star'`，而实现写的是 `Type.ToString().ToLowerInvariant()` ⇒ 真值是 `'githubstar'`（`ItemRepository.cs:603,660`）`[已核实]`。注释不实，我按四闸门 ②③ 直接改注释（不等你拍板，见批次 JH），免得热榜按注释写查询恒空。

## 5. 界面与交互（P-69：只加主窗一页，不加组件）

- **主窗左侧多一页「热榜」**（与 剪贴板 / 待办 / 随记 同级的浏览面）：卡片显示 `fullName`、描述、语言、总 star 数、本期新增 star（缺失时显示"新增星数未知"而非 0）、以及一行来源标注（"来自 GitHub 热榜页 · 每日/每周/每月" 或 "热榜页解析失败，已用搜索接口兜底 · 数据可能偏旧"）。
- 动作：**打开**（`LauncherEx`）、**复制仓库地址**、**收进收藏**、**一键 Star**（写操作，需 Token）。
- 筛选：周期（日/周/月）+ 语言（"全部" + 我从 `InsightsService` 的语言 Top8 里给的常看语言 `[已核实]`，`src/StarMark.Core/Insights/InsightsService.cs:100-107` + 手输其他）。语言候选只是**筛选项**，不参与打分（个性化见 P-71）。
- 刷新：进入页面时若缓存不是同一个本地日历日则抓（照扩展的 `isSameLocalDay`）`[读码转述]`；页内「刷新」按钮强制重抓；抓取失败 ⇒ 回读旧缓存并标 stale，同时给「重试」按钮（C3）。**不加任何常驻定时器**（桌面现状也没有自动同步，`GitHubOptions.SyncIntervalSeconds` 全项目无消费者 `[已核实]`——热榜不去顺手改它）。
- 开关：设置页一张「GitHub 热榜」卡，**默认关闭**，开启后才发第一个请求（与剪贴板历史"默认关 + 用户显式授权"同口径；理由与代价见 P-70）。
- **不做桌面组件。** 理由见 §6：与「今日速览」抢的就是"每天打开看一眼有什么新东西"这一个心智，而"推荐"这个词已经被 Glance 的类注释写上了（`src/StarMark.UI/Views/GlanceWidget.xaml.cs:18` 自称"日期语义 + 推荐入口的组合卡片"，下半屏「常看」= `GetRecentAsync(6)` `[已核实]`）。真要在桌面上看热榜，按 IP/IQ 的先例**取代而不是并存**，且那一次得由你先定"谁让位"。

## 8. 风险与可行性再分析

1. **页面结构会变**（唯一真风险）。缓解：解析失败必须**可见 + 自动兜底 + 回读旧缓存**，且解析器是纯函数 ⇒ 改版时改一个文件、补一条 fixture 用例即可，不会蔓延。这也是我坚持把它放可机检层的原因。
2. **解析外部 HTML 的安全面**：只取"相对路径 `/owner/repo`"重建 `https://github.com/owner/repo`，**绝不直接使用 href 原值**（防 `javascript:`/`data:`/自定义 scheme 混进 `Item.Uri`）；最终打开仍过 `LauncherEx` 白名单。正则只跑在有长度上限的输入上（防放大）。日志不记正文（C6）。
3. **限流**：HTML 腿无配额概念但可能被反爬（返回验证页 ⇒ 解析出 0 条 ⇒ 必须落到"解析失败"分支而不是"今天没有热榜"）；Search API 匿名 60/h，所以兜底也必须**只在需要时用 + 结果同样入缓存**。
4. **不要顺手改的东西**：`GitHubOptions.SyncIntervalSeconds` 无人消费（属既有登记项），热榜不借此引入第一个自动同步定时器；如果哪天真要自动同步，那是单独的决定。
5. **时间戳单位**：扩展全用**毫秒**、桌面 Schema 全用 **Unix 秒**（`Schema.sql:3`）`[读码转述/已核实]`。若将来做方案 C（导入扩展数据）必须显式换算——写在这里是为了不让后来人踩。
6. **`type` 真值与注释不符**：见 §4 末（批次 JH 修）。

## 10. 验收清单（真机 `[v]`，届时随批次补全）

① 未配 Token 也能看到热榜（读侧不依赖 Token）；② 断网/被反爬时页面说的是"抓取失败·已显示上次结果（N 小时前）"+「重试」，而不是空列表；③ 一键 Star 成功后它出现在我的 star 里且下次同步不重复；④「收进收藏」后它在统一搜索、标签格、置顶条目、备份里都按"我自己的 star"表现；⑤ 没点「收进收藏」的条目不出现在收藏计数 / 语言分布 / 健康度分母里；⑥ 关闭开关后应用不再向 `github.com` 发任何请求（可用日志与抓包核对）；⑦ 切周期/语言时不重复抓同日已缓存的键。

## 11. 回退方式

功能整体挂在设置页那一个开关后面（P-70 默认关）：不打开 ⇒ 无新请求、无新表、无 schema 变更、`items` 无新来源。批次 KA-KC 落在可机检层且不被任何现有路径调用，等于天然可回退；KD/KE 是页面与设置卡的增量接线，回退即摘掉导航项与卡片。唯一需要留意的不可逆点是"用户主动收进收藏"后产生的条目——那本来就是用户自己的动作，走既有的删除/隐藏路径即可。
