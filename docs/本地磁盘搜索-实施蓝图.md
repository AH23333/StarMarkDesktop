## 1. 需求与硬约束（勿推翻）
- 目标：像 Everything 一样**全盘、秒出**搜本地文件名。承载组件 = **快捷搜索 / 主窗搜索栏**（**不是**搜索结果格）。
- 已排除路线：A 托管按根目录扫描（配置差异致体验分裂）、B Windows 索引 `Search.CollatorDSO`（受制用户系统设置）、C 读 `Everything.db`（版本锁死）。
- 硬三角：**免管理员 / 不依赖用户配置 / 全盘秒出** 三选二。要"全盘+秒出+不依赖配置"必须直读 `$MFT`+USN ⇒ 必须提权。

## 2. 选定架构（方案 A）
- 一个以 **SYSTEM 常驻的提权后台服务**持有全盘索引，经**命名管道 IPC** 应答查询；**StarMark 主程序保持普通权限**（不整程序 runas）。
- **服务内核复用 Everything**：服务内部托管一个私有 Everything 实例作为索引引擎，对用户完全不可见（工程量减半、最稳）。用户视角"开功能→授权→等待首扫→可搜"，无 Everything 心智负担。
- **开关式生命周期（内存优先）**：默认**关**。关时不装/不启服务、不加载索引 → **额外内存 0**；开启才懒起；关闭即停回落。
- 交互门：`Disabled / NeedsSetup / Starting / Indexing / Ready`。**未授权（NeedsSetup）绝不提示"扫描进行中"**，只有越过授权、真在建立索引（Indexing）才提示等待。

## 6. 可行性再分析 · AC-D2 命名管道客户端「异步/取消」先决契约（CK 批 · 2026-09-21 · pillar-4 需求挖掘）

> 触发：CH 批在既有 `DittoSource` 发现 **P-32 站点②**（`[已核实]`：`Task` 形签名却同步读库、收了 `ct` 从不下传 → 实时搜索路径**逐按键阻塞 UI 线程且不可取消**）。AC-D2 要新建的 `LocalFileIndexSource : IItemSource`（本蓝图 §4 第 23 行）走的是**同一实时源槽位、同一 `SearchAsync(query, filter, ct)` 契约**——若不预先立约，极可能原样复现同缺陷类。本节把这条教训固化为 AC-D2 的**硬先决需求**，使真机批次开工即带护栏，属可读区前瞻、**不改任何现有码**。

**契约现状核实（`[已核实]`）**：`IItemSource.SearchAsync`（`src/StarMark.Abstractions/IItemSource.cs:28`）签名**已带 `CancellationToken ct`**，`SearchService` 实时路径在 `src/StarMark.Core/Search/SearchService.cs:69` 把该 `ct` **原样下传**给每个 `IsAvailable` 的源、随后在 `:77` 经 `SafeAwait(sourceId, task, ct)` 汇聚。**⇒ 接口与编排层无缺陷，缺陷全在源实现自身的异步纪律**（DittoSource 即例证）。因此 AC-D2 的三条要求**全部落在新组件的 `SearchAsync` 实现体内**，与主程序权限模型正交、可独立实现。

**AC-D2 必须先决（写进实现约定，缺一即视为回归 P-32）**：
1. **真异步、不在同步段做阻塞 I/O**：`SearchAsync` 方法体**进入 `await` 前的同步部分**不得包含命名管道的连接/读写（`PipeStream.Read`、`WaitForConnection`、同步 `Flush` 等）——须用 `Stream.ReadAsync(ct)`/`WriteAsync(ct)` 真异步 API，或整体 `await Task.Run(..., ct)` 让出线程池。判据与 `EverythingSource`（真异步经 `EverythingQueryQueue`）对齐，**不得**对齐 `DittoSource`（假异步）。
2. **`ct` 全程下传**：收到的 `ct` 必须真正传给管道 I/O 与任何等待，使 UI 层逐按键取消能**立即中止挂起的管道往返**。吞掉 `ct`（形参在、不消费）即命中 P-32 站点②。
3. **单次查询硬超时**：管道往返须设**独立超时**（`cts.CreateLinkedTokenSource(ct)` + 超时，或服务侧响应超时）。因编排层 `SafeAwait(:77)` 是 `await` 该 task——**若源既不完成又不观测 `ct`，整次统一搜索连 SQLite FTS 结果一起被拖住**。这条是 §2「秒出」体验的守门条件，也是服务被 MFT 锁/冷启占用时的降级保险。

**归属与可测性**：AC-D2 本体（真起服务、真命名管道、真 Everything 私有实例）属 `[v]` 不可沙箱测。但要求 ①②③ 中**「假异步/吞 ct」这一缺陷形态**本身可在纯托管层用**注入的假管道流（`PipeStream` 替身 / 慢速 `MemoryStream`）**做机检回归（断言：进入 `await` 前不阻塞、`ct` 取消时 `SearchAsync` 在有界时间内抛 `OperationCanceledException`、超时后不悬挂）——届时把该测试与 `EverythingSource`/`DittoSource` 的同型契约测试归为一套（承 BU/BV/BW 的源壳契约护栏补测法）。**若未来落地时该假流测试成立，即从 🔵 升为可机检 🟢**，与 P-32 站点②「同源不同实现、异步形/取消可独立修」的定性一致。

**与待决策 P-32 的关系（不冲突、单向收益）**：P-32 站点② 是对**既有** DittoSource 的缺陷登记（用户侧真机批次处理）。本节**不擅自改 DittoSource**（闸门②③不过，仍 🔵），仅把同一教训**前馈**给尚未开工的 AC-D2，使新代码**从设计上规避**已知缺陷类——这是纯 docs 的需求/可行性收敛，零码改、零回归风险。
