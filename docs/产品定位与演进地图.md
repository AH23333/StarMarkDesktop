# StarMarkDesktop · 产品定位与演进地图

> 日期：2026-09-19 ｜ 性质：产品战略决策（定位收敛 + 细分市场纵深地图）
> 背景：功能扩张期的定位审视——收敛掉的是**地图之外的风景**（与收藏生命周期无关的功能），深化的是**地图之内的纵深**（收藏生命周期六环节）。
> **本文件是后续所有功能准入的判定依据。**

---

## 一、一句话定位

> **StarMark —— 个人收藏的统一检索、AI 整理与生命周期管理（本地优先）**

跨源聚合 GitHub Stars / 浏览器书签 / 本地文件 / 剪贴板 / RSS（未来）五类条目，提供从**收集 → 整理 → 检索 → 消费 → 回顾 → 沉淀**的完整收藏生命周期管理。数据 100% 本地，零服务器，零账号。

---

## 二、细分市场与竞争格局

**细分市场**：跨源收藏检索与整理——这个被主流工具忽视的工作流（Stars 进 GitHub 就找不到、书签存了就吃灰、剪贴板转瞬即逝）。

| 竞品 | 定位 | 与本项目关系 |
|---|---|---|
| uTools | 横向通用启动器 + 插件生态（400+ 插件） | **不构成直接竞争**——它不了解你的收藏上下文，做不了跨源收藏的 AI 整理与语义检索 |
| PowerToys | 系统增强套件 | 无收藏管理能力；其 MIT 组件（Crop and Lock/Screen Ruler）是**可移植的实现参考** |
| Rainmeter | 桌面皮肤展示平台 | 无数据层 |
| Notion / 飞书 | 云端知识库 | 需账号、云端存储——与"本地优先"定位相反 |

**护城河**：唯一拥有跨源收藏数据层 + 上下文的工具 → AI 整理标签（理解你半年的收藏轨迹）是 uTools 插件做不到的垂直能力。**往纵深走竞争者越少；往横向走对手越多**——这是定位收敛的战略依据。

## 三、收藏生命周期纵深地图（六环节）

> 每个环节 = 用户问题 × 已有能力 × 深挖空间。**后续功能准入的判定框架**。

### ① 收集 ——"看到有用的东西，怎么最快存进来？"

- 已有：书签/Stars 同步 ✓、剪贴板捕获 ✓、截图 OCR 入库（计划）
- 深挖：**网页全文存档**（防链接失效）、手机 → 桌面捕获通道、**本地实现**：OCR = Windows.Media.Ocr 系统内置（零模型分发）

### ② 整理 ——“存了一堆，乱成一团怎么办？”

- 已有：标签/笔记 ✓、去重合并（URL 变体归一）✓、AI 整理（推荐，§15）
- 深挖：**遗忘提醒**（“这个 Star 半年没动过，还留吗”——纯时间戳规则）、智能归组建议、标签体系治理
- **本地实现**：遗忘提醒 = 纯时间戳规则（零 AI）；AI 整理 = BYOK 按需调用或本地 Ollama（零常驻）

### ③ 检索 ——“想用的时候，怎么最快找到？”

- 已有：FTS5 + 中文分词 + 跨源 ✓、标签过滤 ✓、URL 归一合并 ✓
- 深挖：**语义搜索（BYOK embedding API，向量落盘 SQLite 零常驻）**、自然语言查询（本地 Ollama 用户可选）、拼音/同义词扩展（FTS5 内深耕）
- **内存红线**：不引入本地 embedding 模型（模型分发与常驻内存违反第一性原理，见 §五）

### ④ 消费 ——“找到了，怎么用起来？”

- 已有：一键打开 ✓、贴图对照 ✓（截图系统）、引用到随记 ✓
- 深挖：代码片段快速复制（snippet 类型的自然消费路径）

### ⑤ 回顾/复盘 ——“我这几周都在关注什么？”

- 已有：动态时间线 ✓
- 深挖：**职场汇报生成器**（大白话 + 模板词库 → 职场话术；AI 润色可选）、**收藏质量分析**（重复/死链/遗忘统计——InsightsService 已有基础）

### ⑥ 沉淀/流转 ——“值得长期保留的，怎么固化？”

- 已有：导出（MD/HTML/CSV）✓、备份 ✓
- 深挖：Gist 同步、Markdown 发布

## 四、边界声明（功能准入判定）

**准入问题**：新功能必须通过以下至少一问——

1. **这能改善收藏生命周期的某个环节吗？**（如：AI 整理 = 环节②；语义搜索 = 环节③）
2. **这能降低收藏管理的摩擦吗？**（如：托盘/热键 = 快速进出；开机自启 = 常驻可达）

**已裁定不进入的领域**（维持过滤）：通用 AI 对话、记账财务、密码管理、Dock 栏、窗口管理、皮肤引擎、磁盘分析、股票行情、音乐/天气深度扩展——这些是**地图之外**的风景，无论实现路径多么成熟都不接入（无服务器原则 + 定位聚焦）。

**组件 vs 核心的分层表达**：地图内的能力优先以**组件**形态存在（可插拔、按需显示），核心检索体验保持精简——组件数量可以增长，但**每个组件必须标注它服务的生命周期环节**，无法标注的不做。

---

## 五、本地优先的三条铁律（第一性原理）

1. **内存占用最小化**：无常驻模型、无常驻向量、无常驻推理进程——一切 AI 能力 = 按需 HTTP 调用（BYOK）或系统内置 API（Ocr）+ 结果落盘；功能默认关闭时零资源占用。
2. **数据 100% 本地**：无服务器、无账号、无遥测；云能力一律 BYOK（用户自己的 Key，直连服务商）。
3. **降级可用**：不配置任何 AI/云能力时，所有核心功能（检索/标签/组件/备份/导出）照常工作——AI 是增强层不是依赖层。

> **依赖引入的豁免条件**（§5-4 修订）：轻量（无传递依赖）、MIT 许可、解决**高难度自研风险**——如 NCalcSync（表达式解析）、System.Diagnostics.PerformanceCounter（微软官方）。引入前须在文档记录豁免理由。

## 六、路线图（按生命周期环节排布，替代组件清单式路线）

| 批次 | 环节 | 内容 |
|---|---|---|
| **近期收敛期** | 全局 | 截图交互长尾清偿、CaptureOverlay 拆分、§14 性能清单落码、发布配置补全（R2R/PGO/ServerGC） |
| 批次 A | ② 整理 | **AI 基础层**（Provider 三家 + isAiConfigured + 计量预算系统 + 设置页） |
| 批次 B | ② 整理 | **职场汇报生成器**（模板词库 L0 + AI 润色 L1）+ **日程提醒**（待办级） |
| 批次 C | ② 整理 | **AI 批量分类**（两阶段 + 规则预分类 + token 优化全套，见 §19） |
| 批次 D | ③ 检索 | **语义搜索**（BYOK embedding + 向量落盘 SQLite）+ 拼音/同义词 FTS 深耕 |
| 批次 E | ⑤ 回顾 | **收藏质量分析**（重复/死链/遗忘提醒——纯规则）+ 日报素材聚合完善 |
| 批次 F | ① 收集 | 网页全文存档、OCR 入库完善 |
| 远期 | ⑥ 沉淀 | Gist 同步、Markdown 发布 |

## 七、迷茫感的解药（写给未来的自己）

组件数量可以增长（插件化允许），但**增长必须由这张地图驱动**——每次想加功能，先问它属于哪个环节、解决了什么用户问题。如果答案是“好像都不属于”，那它就是地图外的风景——欣赏可以，搬进来不行。

细分市场不是“一个功能”，是“一个被忽视的用户工作流”。工作流有六个环节，每个环节都有深水区——**深挖六年也挖不完，这才是不会迷茫的底气**。
