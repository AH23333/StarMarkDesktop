# StarMarkDesktop 组件功能扩展：可行性分析与实现技术路线

> 日期：2026-09-19 ｜ 基线：全方位改造 Phase 0-5 完成后（`0f31247`）
> 输入：《代码洞察与重构计划》+ 市面工具调研（PowerToys / DeskBox / TrafficMonitor / Catime / Snipaste / Focus Task / 优效日历 / 火柴 等）
> > **配套文档**：[组件功能扩展实现详解.md](组件功能扩展实现详解.md) —— 各功能的**代码级实现**（核心代码 / 落地步骤 / 漏洞预测 / 性能问题），与本文配对使用。

结论先行：**8 项功能全部可在现有架构内实现**，其中 6 项低风险、2 项中风险；**截图贴图按三级路线推进**（MVP → 增强 → 完全体），Snipaste 级"像素级边缘吸附"明确列为远期目标而非首发承诺。

## 一、前提与约束

| 项 | 内容 |
|---|---|
| 技术栈（不可更换） | WinUI 3（Windows App SDK 2.4）+ .NET 9 + C# + MVVM + DI + SQLite |
| 依赖纪律 | **不引入新 NuGet 包**——系统监控用 PDH/Win32 P/Invoke 而非 PerformanceCounter 包，截图用 GDI BitBlt P/Invoke 而非 System.Drawing.Common |
| 分层纪律 | Win32 / 图形 API 只允许出现在 `StarMark.Integrations` 与 `StarMark.UI`；纯逻辑（计时状态机、表达式求值、监控模型）必须下沉 `StarMark.Core`（可测试，见踩坑 #57） |
| 组件接入纪律 | 新组件走 `WidgetKind` / `WidgetRegistry` / `WidgetContentFactory` **三处同步注册**（踩坑 #47） |
| 性能预算 | 常驻内存增量目标 ≤ 30MB；监控类组件采样期 CPU < 1%；截图遮罩窗仅在选择态存在（确认即销毁或转入贴图） |
| 已排除 | 白噪音 / 专注音（发起人裁定：使用人群过少，移出清单） |

## 二、逐功能可行性分析

### 2.1 番茄钟 / 专注计时 🟢 低风险

**功能定义**：25+5 循环（可自定义时长）、可从 Todo 条目一键开始专注、常驻小窗倒计时、阶段结束 InfoBar/托盘提醒、可选统计（今日完成番茄数）。

**技术方案**：
- 纯逻辑：`Core/Widgets/FocusTimer.cs` —— 有限状态机（Idle / Focusing / Resting / Paused），`DispatcherTimer` 驱动（单实例复用，踩坑 #11），状态变更事件；
- UI：`FocusTimerWidget.xaml`，显示剩余时间 + 当前专注的 Todo 文本 + 开始/暂停/跳过；
- 联动：Todo 组件与 FocusTimer 共享 `WidgetInstanceConfig`（或独立 JSON 节），开始专注时携带 todoId；
- 提醒：阶段结束走现有 InfoBar / 托盘气泡；可选系统提示音（`MediaElement` 播放内置资源，见白噪音裁剪说明——仅提示音，非常驻播放器）。

**工作量**：3–5 人日 ｜ **风险**：低（无系统 API、无权限、无数据迁移——数据随 WidgetStoreData v3 序列化即可）。

**集成点**：`WidgetRegistry` 描述符（DefaultWidth ≈ 220）+ `WidgetContentFactory` builder + `WidgetKind.Focus = 12`。

---

### 2.2 倒计时 / 纪念日 🟢 低风险

**功能定义**：多个命名倒计时（截止日时刻 + 标题），显示剩余 天/时/分；纪念日显示"第 N 天"；到点提醒。支持从剪贴板/选定文本快速创建。

**技术方案**：
- `Core/Widgets/CountdownModel.cs`：纯数据 + 剩余时间计算（跨午夜/闰年由 `DateTimeOffset` 处理）；
- 持久化：`WidgetStoreData.Instances` 每实例自带 `CountdownItems`（复用实例内容规范化管线）；
- 提醒：复用 2.1 的提醒通道。

**工作量**：2–3 人日 ｜ **风险**：低（时区陷阱：统一存 `DateTimeOffset` + IANA 时区名，比较用 UTC）。

---

### 2.3 桌面日历 / 月视图 🟢 低风险

**功能定义**：月历网格（今日高亮、节假日角标），点击某天显示**当天的收藏/动态条目**（复用主库 `items` 表按时间过滤），双击跳转主窗对应视图。

**技术方案**：
- WinUI 内建 **`CalendarView`** 控件直接满足月历网格与节假日标定（`CalendarViewDayItemChanging` 定制角标）；
- 当日条目：`IItemRepository` 新增 `GetByDateRangeAsync`（FTS 表已有 `updated_at` 索引，SQL 简单）；
- 数据：零迁移，只读主库。

**工作量**：3–5 人日 ｜ **风险**：低（`CalendarView` 是官方控件，注意其虚拟化与 DayItem 定制的事件节流）。

---

### 2.4 世界时钟 🟢 低风险

**功能定义**：多城市并列显示（城市名 + 时区 + 时间），支持增删，秒级刷新；Glance 组件可嵌入次要点位。

**技术方案**：
- `TimeZoneInfo`（.NET 内建）+ Windows IANA 映射（`TimeZoneConverter` 不可引入——用 `TimeZoneInfo.FindSystemTimeZoneById` 的 Windows Id 即可，仅面向 Windows 平台）；
- 每分钟刷新（复用 Clock 组件的计时器实例模式，踩坑 #11）；
- 城市列表持久化于实例配置。

**工作量**：1–2 人日 ｜ **风险**：极低。

---

### 2.5 快速计算器 🟡 中低风险

**功能定义**：表达式求值（四则 + 括号 + 幂/百分比）、历史记录栈、单位换算（长度/重量/温度/时间戳 ↔ 日期）、结果一键复制。

**技术方案**：
- 表达式求值：`Core/Calc/ExpressionEvaluator.cs` —— 自写 **Pratt / 递归下降解析器**（~200 行，双精度，支持一元负号与常量 pi/e），**不引入 NCalc/DynamicExpresso**（依赖纪律）；
- 单位换算：`Core/Calc/UnitTables.cs` 纯静态表 + 线性换算（温度用仿射）；
- 时间戳换算：Unix 秒/毫秒 ↔ 本地/UTC 时间（开发者高频）；
- UI：`CalcWidget.xaml` 输入行 + 结果行 + 历史列表。

**工作量**：3–4 人日（解析器测试占 1 天）｜ **风险**：中低（浮点精度显示策略：`G15` 去尾零；禁止 `eval` 类动态编译）。

---

### 2.6 系统监控悬浮格 🟡 中风险

**功能定义**：网速上下行、CPU 占用、内存占用三行实时显示（1s 采样），紧凑/完整两档外观；可选仅显示其中一行（Capsule 态）。

**技术方案**（全部 Win32 P/Invoke，零 NuGet，落 `StarMark.Integrations/SystemMonitor/`）：
- **网速**：`GetIfTable2`（iphlpapi.dll）两次采样差值 ÷ 间隔 → 上下行字节速率（汇总所有 up 接口，排除 loopback）；
- **CPU**：`GetSystemTimes` 两次采样差值 → 占用率；
- **内存**：`GlobalMemoryStatusEx` → 物理内存占用率；
- 采样器：`StarMark.Core/Widgets/SystemMonitorModel.cs` —— 单例采样循环（1s，仅存在可见实例时运行；无实例即停止，零闲置开销），线程安全快照供 UI 读取；
- UI：`SystemMonitorWidget.xaml`，1s `DispatcherTimer` 只做取快照 + 渲染。

**工作量**：5–8 人日（P/Invoke 签名与结构体对齐占 2 天，踩坑 #55 同类）｜ **风险**：中——PDH 类指标（CPU）在采样窗口极短时抖动，需 2s 滑动平均；接口流量在 Wi-Fi 切换时归零属正常，需显示容错。

**性能预算**：采样循环 O(接口数)，内存 < 1MB，CPU < 0.5%（1s 间隔）。

### 2.7 护眼 / 休息提醒 🟢 低风险

**功能定义**：可配置间隔（默认 45min）提醒休息；可选"强制模式"——全屏淡入半透明遮罩 + 倒数 20s 解锁（Esc 不跳过，防形同虚设；也可关闭强制）。

**技术方案**：
- 计时：`Core/Health/EyeRestPolicy.cs`（纯逻辑：工作/休息节拍 + 暂停窗口期——检测全屏应用时延后，通过 `GetForegroundWindow` 的窗口矩形 ≈ 屏幕矩形判定）；
- 遮罩窗：**与截图遮罩窗共享同一技术件**（见 2.8 的 `OccluderWindow`）——全屏半透明 + 倒数文案，淡入动画；
- 通知：非强制模式走 InfoBar/托盘气泡。

**工作量**：2–3 人日（依赖 2.8 的遮罩技术件先行）｜ **风险**：低（遮罩窗必须 `Topmost` 且处理多显示器，复用 2.8 的多屏方案）。

### 2.8 屏幕截图 / 贴图 🔴→🟡 高价值高风险（三级路线）

#### 2.8.0 与 Snipaste 的差距本质

Snipaste（C++/Qt 原生）的"快速便捷"由四层能力堆叠：① 毫秒级全屏捕获与遮罩呈现；② **窗口树探测**（WindowFromPoint + 窗口矩形级联）+ **像素级边缘吸附**（对截图像素做梯度分析，自动吸附到 UI 元素边界）；③ 基于分层窗口（`WS_EX_LAYERED | WS_EX_TRANSPARENT | WS_EX_NOACTIVATE` + `UpdateLayeredWindow`）的贴图窗（像素级 Alpha、点击穿透、缩放/旋转/透明度）；④ 完备的标注编辑器。**①③ 是工程确定性能力（C#/WinUI 可达成）；② 的像素级边缘检测是 Snipaste 的核心壁垒，C# 托管实现可达"窗口矩形级"吸附，"像素级"需非托管图像处理，成本陡增**。

#### 2.8.1 三级实现路线

**L1 · MVP（8–12 人日）——先达成"可用且快"**：

| 环节 | 方案 |
|---|---|
| 触发 | 复用 `HotkeyService` 注册全局热键（默认 F1，可改） |
| 捕获 | `StarMark.Integrations/Capture/GdiScreenCapture.cs`：`GetDC(NULL)` + `CreateCompatibleDC` + `BitBlt` 逐显示器捕获（多屏 = 每屏一次，按虚拟屏坐标拼接），**全程 P/Invoke，零 NuGet**；捕获耗时实测通常 < 50ms |
| 遮罩选择 | 每显示器一个全屏 `OccluderWindow`（WinUI Window：`SetWindowPos` 覆盖屏幕、Topmost、半透明暗化背景），其上 `Canvas` 绘制选区矩形 + 尺寸提示；鼠标十字光标 |
| 确认 | 按下-拖拽-抬起完成选区 → 从已捕获位图裁剪 → 进入"贴图"或"复制/保存"三选快捷条（Enter=贴图，Ctrl+C=复制，双击=保存） |
| 贴图窗 | 无边框 `PinWindow`（复用 WidgetWindow 外壳模式：去边框 + Topmost + 拖动 grip），`Image` 显示裁剪结果；滚轮缩放（0.2×–5×，保持清晰度用 `DecodePixelWidth` 级解码）；右键菜单：复制 / 保存 / 透明度 / **鼠标穿透开关** / 关闭 |
| 点击穿透 | `WindowInterop` 扩展：`WS_EX_LAYERED \| WS_EX_TRANSPARENT`（穿透时）——P/Invoke 落 `Integrations/Win32/` |
| 多显示器 | 遮罩窗每屏一个；贴图位置按 DIP + 每显示器拓扑（复用 `WidgetLayout` 的显示器标识方案，踩坑 #55） |
| Esc 取消 | 全部遮罩窗/贴图态 Esc 退出（踩坑 #32 的根挂法） |

**验收标准（对标"快速便捷"的下限）**：热键到遮罩呈现 < 150ms；选区确认到贴图出现 < 100ms；多屏/DPI 正确；穿透贴图可用。

**L2 · 增强（+5–8 人日）——向 Snipaste 靠拢**：
- **窗口矩形探测**：`WindowFromPoint` + `GetAncestor` + `GetWindowRect` 构造可见窗口矩形集（含 Z 序去重叠裁剪），鼠标悬停自动高亮吸附窗口级边界——Win32 确定性能力，C# 完全可行；
- 放大镜（8×/16× 像素预览 + 颜色值）、RGB 取色器；
- 贴图管理：贴图列表、一键全部显示/隐藏（托盘菜单）；
- 简单标注（矩形/箭头/文字/马赛克）——基于 WinUI `Canvas`/`InkCanvas`。

**L3 · 完全体（远期，不承诺时点）**：
- **像素级边缘吸附**：捕获位图的 Sobel/梯度分析 + 积分图加速（托管代码 1080p 屏 ~30ms/帧可行，但需 C# unsafe + `ArrayPool` 严控分配）；
- 分层窗口截图（Shift 滚轮选 Z 序窗口）、滚动长截图、GIF 录制。
- **决策点**：L3 若确认投入，评估将图像处理下沉为独立 C++/WinRT 原生组件（需违反"无新依赖"的豁免审批）——在此之前 L2 已覆盖 90% 日常场景。

#### 2.8.2 风险与缓解

| 风险 | 缓解 |
|---|---|
| 全屏游戏/独占模式下 BitBlt 捕获黑屏 | MVP 明确不支持独占全屏（提示用户窗口化）；后续可评估 DXGI Desktop Duplication（P/Invoke，工作量 +3 人日） |
| WinUI Window 做全屏遮罩的呈现延迟 | 预热：常驻**隐藏**遮罩窗池（显示前已初始化），显示仅切 Visible + 置位图 |
| 贴图窗内存 | 每张贴图 ~位图大小（4K 屏全屏贴图 ≈ 33MB）——限制同时贴图数提示 + 关闭即释放；贴图窗**不在** WidgetManager 生命周期内（独立轻量管理器 `PinManager`） |
| 与现有全局热键冲突 | HotkeyService 已有冲突检测与提示（复用） |
| **架构不破坏性** | 捕获/穿透/窗口枚举全部落 `Integrations`；遮罩/贴图窗是**独立窗口族**（不进 WidgetManager、不进 WidgetRegistry——它们不是"组件"而是"工具窗"），`Core` 仅存纯模型（选区矩形、贴图元数据）；不触碰数据层 |
| **臃肿防线** | 截图子系统独立命名空间（`Integrations/Capture` + `UI/Screenshot/`），与组件体系零交叉；L1 完成后按使用数据决定 L2/L3 投入 |

## 三、横切事项

1. **WidgetRegistry 三处同步**（坑 #47）：Focus/Countdown/Calendar/WorldClock/Calc/Monitor 六个新组件各改三处——建议本轮顺手落地 `代码洞察与重构计划.md` T13 的 `[Widget]` 特性反射注册，把三处合并为描述符一处（1 人日，一劳永逸）。
2. **性能预算核算**：全部上线后常驻增量 ≈ 监控采样 0.5% CPU + 各组件 UI 内存（预估合计 ≤ 30MB）——符合 §二 预算；`MemoryReclaimer` 现有机制继续兜底。
3. **测试策略**：Core 纯逻辑（状态机/表达式/监控模型/倒计时计算）进 xUnit；截图链路的 GDI P/Invoke 无法单测——走 SmokeTest 无头模式（`-- capture` 捕获一张位图并校验非全黑 + 尺寸正确）；守门测试（主题画笔）自动覆盖新 UI。
4. **文档**：每个组件上线同步 `docs/组件重构R3收官阶段工作文档.md` 风格的阶段记录；`踩坑记录.md` 持续追加（P/Invoke 结构体对齐大概率出新坑）。

## 五、架构不破坏性论证（小结）

1. **分层零污染**：新逻辑全部遵守"纯逻辑下沉 Core、系统 API 进 Integrations、渲染进 UI"；`Core/Data/Abstractions` 不新增任何 Windows 专属引用（§5-7 保持）。
2. **组件体系零侵入**：截图/贴图是**独立工具窗族**（PinManager/OccluderWindow），与 WidgetRegistry 组件体系**完全解耦**——删除整个截图子系统不影响任何既有组件。
3. **依赖零新增**：全部系统级能力（GDI 截图、PDH/系统计时、窗口枚举、点击穿透）走 P/Invoke，落 `Integrations/Win32/`。
4. **性能预算受控**：常驻增量 ≤ 30MB / 监控 CPU < 1%；截图遮罩为瞬态资源（选择态才存在）；贴图窗按需创建关闭即释放。
5. **臃肿防线**：每批次上线后复评——若某组件使用率极低（如发起人裁掉白噪音的同类判断），按同一标准回撤。

| **汇率换算（自股票行情拆分单列）** | 股票实时行情维持过滤（无免费稳定源）；**汇率有 Frankfurter API**（ECB 数据/免费/无 Key/开源）+ 24h 本地缓存，作为计算器组件的货币换算标签接入 |

### 维持过滤（9 项，理由与实现路径无关）

| 功能 | 维持理由 |
|---|---|
| 股票实时行情 | 免费无 Key 的实时行情源不存在（Frankfurter 仅覆盖汇率） |
| Rainmeter 式皮肤引擎 | 工程量源于皮肤脚本生态而非实现路径；与原生 WinUI 组件路线冲突 |
| 窗口管理（FancyZones 类） | PowerToys 为事实标准，重复实现无优势 |
| 密码管理器 | 凭据加密存储与审计的安全责任不因成熟库转移 |
| Dock 栏 | 与任务栏/开始菜单直接竞争，WinUI 实现成本高且难超原生 |
| 记账 / 财务面板 | 数据模型与报表体系偏离核心定位 |
| 天气雷达 / 通勤交通深度 | 依赖不稳定第三方 API；基础天气组件已有 |
| 录屏 / 录音 | **有条件解封预留**：与截图 L2 共用 Windows.Graphics.Capture 基础设施，落地后增量成本下降——挂起至 L2 验收后二次评估 |
| 磁盘空间分析（WizTree 类） | 文件检索需求已由 Everything 集成覆盖 |
| AI 对话窗 | 定位漂移（通用聊天 ≠ 收藏整理），LLM 成本持续；**重新评估触发条件**：若 AI 整理能力扩展出"针对收藏的自然语言查询"需求，以"语义查询"形态重审而非通用对话 |
