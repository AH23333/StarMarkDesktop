# StarMark v1.0.3

程序能力与 v1.0.2 相同。这一版改的是**更新过程中你看得见什么**：下载那一段现在有读数，装完之后新写了什么也能就地读到。

**运行前请先装 [.NET 9 Desktop Runtime](https://dotnet.microsoft.com/download/dotnet/9.0)**。解压 `StarMark-1.0.3-win-x64.zip` 到任意目录，运行 `StarMark.UI.exe`。

## 怎么升上来

打开 StarMark → 设置 → 「关于与更新」→ 看到「有新版本 v1.0.3」后点「立即更新」。程序下载载荷、核对清单签名与逐文件 SHA-256，再由独立更新器替换文件。

**从 v1.0.2 升上来的这一次，替换失败会把你原来那一版重新起来。** 上一版的发布说明里那句"这最后一句对升到这一版的这一次还做不到"，从这一版起不再是这样：v1.0.2 已经带着修好的更新器，而替换用的更新器就是从**你当前装着的那一版**里拿出来的。所以从 v1.0.0／v1.0.1 直升 v1.0.3 的话，中间那一跳仍由旧更新器执行——那种情况下万一撞上"安装目录挪不动"，你看到的还是旧样子（程序停下、本机一个字节不改、日志写明原因，但不会自己把窗口重新开回来，手动再开一次即可）。

## 这一版具体改的两件

- **下载那 70 多 MB 不再是一句静止的话**：以前点完「立即更新」，界面上那一行从点下去到下一步之间一个字都不变，与"卡住了"在屏幕上长一样。现在它跟着实际写到盘上的字节走，说的是"已下多少／共多少（百分之几）"。两件事故意不做：**不写 100%**（那一段走完就换成"正在核对签名"，100% 在屏幕上读起来像结局），**不写速度和剩余时间**（那两个数在网络上说不稳，说不稳的话就不上屏幕）。总长那一格取的是对方声明的长度；对方没声明，就只报"已下多少"，不编一个总数把百分比凑满。
- **「这一版的更新说明」在设置页能直接读**：检查到新版之后，同一张卡上多一个可展开的「这一版的更新说明」，把发布页上写的那段话收成纯文本给你读（标题记号、加粗星号、链接地址这些写法噪声会被去掉）。

## 已知边界（说清楚，免得被当成坏了）

- 那段更新说明**不写进你的配置文件**，所以**重启程序后那一格是空的**——它只在一次检查之后当场可见，再点一次「立即检查」就回来。这样做的理由：你的配置文件会被自动备份打包、也会被同步推上远端，把一段由外部服务器写的、长度不定的文字存进去，等于把它一起复制走；更要紧的是它会在下一版发布之后继续冒充"这一版的说明"。
- 下载之外的两步（核对清单、把新版本摊开到暂存区）仍然只有"正在做什么"这一句，没有读数。摊包实测一两秒，不是值得为它加进度条的那一段。
- 这一版**没有改更新器本身**，所以"换不成会自己把旧版重新起来"这条兜底，保护的是装上 v1.0.2 之后的每一跳（包括这一跳）；更早那两版升上来的中间跳仍是旧行为。
- 如果这台机器不许在安装目录旁边写文件（装在受保护位置、或盘只读），更新会在"摊开新版本"那一步停下，界面说的是"本机写不出暂存文件（磁盘满或没权限），更新没有开始"——这一条不会让你看到空屏幕，因为程序还没退出。
- 更新只走 GitHub 上这一个仓库，载荷要过签名与逐文件哈希两关；任一处对不上就不装，本机一个字节都不改。
- 本地文件搜索只按**文件名**找，不搜文件内容（这是产品边界，不是缺陷）。
