# StarMark v1.0.8

这一版是个大版本，主角是**「把文件放进去」**：待办行文件附件、剪贴板组件拖入、虚拟文件物化链三条路一次配齐。此前从浏览器往 StarMark 拖一张图、从邮件客户端拖一份附件，多半只得到一条链接或干脆没反应；现在这类「只有内容、没有路径」的虚拟文件会被如实收进程序自己的托管目录，贴出去、再打开还是原来那份。自 v1.0.7 以来这一版积了 22 个提交。

**运行前请先装 [.NET 10 Desktop Runtime](https://dotnet.microsoft.com/download/dotnet/10.0)**（v1.0.5 起的硬要求）。解压 `StarMark-1.0.8-win-x64.zip` 到任意目录，运行 `StarMark.UI.exe`；或者用 `StarMark-1.0.8-setup.exe` 安装。

## 怎么升上来

打开 StarMark → 设置 → 「关于与更新」→ 看到「有新版本 v1.0.8」后点「立即更新」。程序下载载荷、核对清单签名与逐文件 SHA-256，再由独立更新器替换文件；**更新完成后会自动弹出这一版的更新说明**（本版新加的能力）。

从 v1.0.7 升上来**不换运行时**，直接点「立即更新」即可。

## 这一版具体改的几件

1. **待办行文件附件。** 把文件拖到任意待办行上即可挂附件：默认「链接」模式不动你的文件，来自临时/缓存目录的自动改为复制；行上出现回形针计数，点开可逐个打开或移除。
2. **剪贴板组件拖入。** 文件或文本拖进剪贴板格，立刻记一条历史——拖进来＝可再贴出。拖入只记历史，不改写系统剪贴板；敏感形状（私钥、银行卡号一类）照旧不记。
3. **虚拟文件物化。** 浏览器拖图、邮件附件这类没有真实路径的虚拟文件，会按磁盘余量钳住暂存预算后物化进托管目录，标上网络来源（MOTW）、缺扩展名的按文件内容补——待办行与剪贴板两条路都吃得下。
4. **拖入文件的账全配齐。** 剪贴板设置卡新增「拖入文件占用」一行（可一键清理孤儿）；启动时对账，孤儿只记日志不动文件；**备份与恢复现在带拖入文件**——「导出时带上」那颗开关因此改叫「附件」口径，管图片、画板、拖入文件三族。
5. **更新完成自动弹更新说明。** 更新装完自动弹出这一版改了什么，不用再自己去翻发布页；设置里可以关掉只留静默记账。
6. **标签筛选修复。** 选中标签后标签云会整体下移三十余像素、点偏落空且「选了清不掉」——改为常驻状态条三态同高零漂移，单颗 ✕ 与一键清除都真清除。
7. **组件窗口治理。** 整屏被外来窗口盖住时，桌面组件按隐藏同款五分钟宽限收起，露出来后分帧复原；此前用户报告的一类组件窗口崩溃（stowed exception，根因在 WinApp SDK 环境层）加了双刀缓解——半死窗口不再被拆毁消息找到，退出前多泵一拍。
8. **画板主题独立。** 画板跟随系统/浅色/深色自选，不再与主窗绑定。
9. **授权换轨 GPL-3.0。** 本仓库自 2026-11-26 起整体换轨 GPL-3.0（此前 MIT），LICENSE 随每一份发行拷贝走。

## 已知边界（说清楚，免得被当成坏了）

- **.NET 10 运行时是硬要求**（见上面那段加粗）。
- 虚拟文件物化的实证面是 **Chromium 内核浏览器拖图**；Outlook 附件等其它来源理论上走同一映射，未逐一实证。
- 物化按磁盘余量钳暂存预算（给系统留量），备份恢复解拖入文件单件上限 2GB：超限的件会被拒收或如实报「没带」，不会悄悄截半份。
- 组件窗口那类崩溃的**根因在 WinApp SDK 环境层**（0xc000027b、零托管帧），本版是缓解不是根治；再遇到请把崩溃 dump 发过来。
- 本地文件搜索只按**文件名**找，不搜文件内容（这是产品边界，不是缺陷）。
- 更新只走 GitHub 上这一个仓库，载荷要过签名与逐文件哈希两关；任一处对不上就不装，本机一个字节都不改。
