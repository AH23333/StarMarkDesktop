# StarMark v1.0.7

这一版是个小版本，一件主角：**AI 自动分类的稳健性修复**——针对「思考型」大模型（推理消耗大、免费档常见）的三连修复：输出帽地板上调、截断如实分型、被截断的批升帽自动重发。此前这类模型会让 AI 分类批量失败并误报成「协议不配」一类的不相干错误，现在要么一次答完，要么把真实原因如实报出来。自 v1.0.6 以来这一版积了 7 个提交，用户看得见的就是这一件。

**运行前请先装 [.NET 10 Desktop Runtime](https://dotnet.microsoft.com/download/dotnet/10.0)**（v1.0.5 起的硬要求）。解压 `StarMark-1.0.7-win-x64.zip` 到任意目录，运行 `StarMark.UI.exe`；或者用 `StarMark-1.0.7-setup.exe` 安装。

## 怎么升上来

打开 StarMark → 设置 → 「关于与更新」→ 看到「有新版本 v1.0.7」后点「立即更新」。程序下载载荷、核对清单签名与逐文件 SHA-256，再由独立更新器替换文件。

从 v1.0.6 升上来**不换运行时**，直接点「立即更新」即可。

## 这一版具体改的几件

1. **输出帽地板 400→2400。** AI 分类的单批输出上限此前低至 400 token，「思考型」模型的推理消耗会把它整个吃光、正文一个字不剩，随后被误报成「choices 里没有正文（这个端点可能不支持 chat 形式）」这类协议错误。地板上调到 2400 后，绝大多数批一次就能答完。
2. **截断如实分型，不再误诊。** 真的截断时按服务商返回的结束原因分三态处理：正文全被截断＝按「被截断」如实报（不再误报协议错误）；答了一半被截断＝照收已答部分的提案并标注「有 N 批没答完」；正常答完＝与旧版零差。
3. **被截断的批升帽自动重发。** 单批被输出帽切断零正文时，自动把帽推到 4000 上限立即重发一次（不是等一等再撞同一堵墙）；重发仍截断才收口。两次请求的真实用量并成一笔如实入账——「花了两次只记一次」的漏账不再发生；被截断的失败批也一样把服务侧已计费的真实用量入账。

## 已知边界（说清楚，免得被当成坏了）

- **.NET 10 运行时是硬要求**（见上面那段加粗）。
- 「思考型」模型的推理消耗**没有上界保证**：极少数批可能连 4000 帽也撞（表现为「有批没答完」而不是装坏）；换非思考模型或稍后重跑即可。
- 本地文件搜索只按**文件名**找，不搜文件内容（这是产品边界，不是缺陷）。
- 热键若被其它程序占用（如个别机器上的 Ctrl+Alt+P），注册失败会留一行日志，其余热键不受影响。
- 更新只走 GitHub 上这一个仓库，载荷要过签名与逐文件哈希两关；任一处对不上就不装，本机一个字节都不改。
