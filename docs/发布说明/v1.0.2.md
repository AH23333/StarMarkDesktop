# StarMark v1.0.2

程序能力与 v1.0.1 相同。这一版改的是**自动更新本身**：升级没做成的时候，你眼前的程序不该消失。

**运行前请先装 [.NET 9 Desktop Runtime](https://dotnet.microsoft.com/download/dotnet/9.0)**。解压 `StarMark-1.0.2-win-x64.zip` 到任意目录，运行 `StarMark.UI.exe`。

## 已经装了 v1.0.1 的人怎么升

1. 打开 StarMark → 设置 → 「关于与更新」；
2. 看到「发现新版本 v1.0.2」后点「立即更新」；
3. 程序下载载荷、校验清单签名与逐文件 SHA-256，再由独立更新器替换文件；
4. 换成功 → 新版本自己起来；换不成 → 要么退回原来那一版，要么压根没动过安装目录，**两种都会把原来那一版重新起来**。

## 这一版具体改的两件

- **点「立即更新」之后窗口都不见了**：这一句以前真的会发生。程序为了把文件让给更新器会先退出，而更新器在某些"还没碰到安装目录就不得不停"的情况下只写了一行日志就走人——屏幕上什么都不剩，唯一线索是日志文件。现在这些情况会把你原来那一版重新起来；连这一步也起不来时，会单独说一句"程序此刻没开着"，不再混在"本机什么都没改"里。
- **那句提示不再猜原因**：以前失败会写成"旧目录此刻挪不动（有别的东西在用它）"。而"挪不动"在这台机器上至少有三种成因（文件被别的进程占着、权限不许改名、只读盘或策略挡着），程序拿到的只有两种异常类型，分不出是哪一种——所以那句话里括号的部分是猜的。现在只说它真知道的：本机还是原来那一版，程序也已经重新起来，具体原因写在日志里。

## 已知边界（说清楚，免得被当成坏了）

- 如果这台机器根本不许在这棵安装目录旁边写文件（比如装在了受保护的位置、或者盘是只读的），更新会在"摊开新版本"那一步就停下，界面说的是"本机写不出暂存文件（磁盘满或没权限），更新没有开始"——这一条**不会**让你看到空屏幕，因为程序还没退出。
- 有极少数更早的失败时刻（更新器刚起来就发现该换的那棵树已经不在盘上了，比如被清理软件删掉了）仍然只写日志、不重开程序。这一条已经记在案，下一版处理。
- 更新只走 GitHub 上这一个仓库，载荷要过签名与逐文件哈希两关；任一处对不上就不装，本机一个字节都不改。
- 本地文件搜索只按**文件名**找，不搜文件内容（这是产品边界，不是缺陷）。
