## 二、按模块分类的重构与改进意见

### 2.1 数据层 `StarMark.Data`（ItemRepository / DbConnectionFactory）
- **性能（MED）**：`UpsertOne` + `UpsertTagLink` 逐条往返（N+1 写入，`ItemRepository.cs:483-723`）；`GetAllAsync` 每行一个 `GROUP_CONCAT` 相关子查询（`:385-389`，FolderTree 取 `Limit=2000` → 2000 次子查询）；`SearchAsync` 每次额外 `SELECT COUNT(*) FROM items_fts`（`:121-126`，全索引扫描，高频触发）。
- **硬编码**：`Limit=2000`（`FolderTreePageViewModel.cs:148`）、`Everything 20000`（`EverythingInterop.cs:154`）、`MaxResults` 默认 `100`（`IItemSource.cs:55`）。
- **改进**：同步前一次性 `SELECT id,name FROM tags` 建内存字典，标签写入改批量 `VALUES`；列表查询改「主查询 + 一条 `GROUP BY item_id` 聚合」两趟替代每行子查询；连接复用 / PRAGMA 只设一次（`DbConnectionFactory.cs:27-38`）；健康度改用聚合 SQL 而非 `int.MaxValue` 捞全表（`SettingsPageViewModel.cs:142`）。

### 2.2 组件层 `Core/Widgets` + UI `WidgetManager/WidgetWindow/WidgetStorage`
- **可扩展（MED）**：新增组件须同步改 3 处（枚举 `WidgetKind` + `WidgetRegistry.CreateDefaults` + `WidgetContentFactory.CreateDefault`）；`WidgetStorage.cs:287-289` 的 v2→v3 迁移用 `if/else if (kind)` 分流各类内容集合（**最重的类型分发坏味道**）；`WidgetWindow.xaml.cs:88,123,146,778` 把 Clock/QuickLaunch 特例写死在宿主。
- **硬编码**：`0.72` 不透明度重复于 5 处（见 §三）。
- **性能（MED）**：`WidgetStorage.Load()` 每次全量读文件+反序列化+`Normalize`，无缓存（被 `WidgetManager` 高频调用，`WidgetManager.cs:82-279`）；`Save` 用默认严格编码器致 CJK 转义（`WidgetStorage.cs:231`，与 `BackupService` 不一致）。
- **改进**：用 `[Widget(Kind, Title, Glyph, DefaultSize)]` 特性 + 启动期反射扫描合并三处注册；引入 `IWidgetContentSerializer` 让组件自持内容读写，消除迁移 `if/else`；`IWidgetLifecycle` 接口（或描述符标志位）下沉 Clock/QuickLaunch 特例；`WidgetStorage`/`SettingsStore` 加内存缓存，并统一 `JavaScriptEncoder.UnsafeRelaxedJsonEscaping`。

### 2.3 快捷键层 `HotkeyService`（设计最佳，minor）
- 字典分派 + 兜底处理器（`HotkeyService.cs:22,67`），组件动作由 `WidgetKind` 动态拼出（`Hotkey.cs:155-160`），新增组件自动多 4 个动作。**可改**：`HotkeyActions.DisplayName`（`Hotkey.cs:194-219`）仍手写 `switch`，建议与动作 id 一起注册显示名工厂。

### 2.4 设置层 `SettingsStore` + `SettingsPage`
- **可扩展（偏弱）**：一个设置 = 4 份镜像（JSON 字段 / `LoadX`+`SaveX` 方法 / VM 属性 / XAML 绑定），默认值散落多处，`0.72` 即一例；新增设置须改 4~5 文件。
- **God class**：`SettingsPage.xaml.cs` 670 行。
- **改进**：引入 `record SettingDef<T>(Key, Default, Read, Write)` 描述符集合，`SettingsStore` 统一遍历读写，默认值只一处；把 `SettingsStore` 注册进 DI 并注入（见 2.7）。

### 2.5 UI 页面层（FolderTree / Search / Tags / Activity）
- **性能 HIGH**：搜索每次按键即时全量 FTS+Everything 无去抖（`SearchPageViewModel.cs:313-316`）；文件夹树 UI 线程一次性建最多 2000 条（`FolderTreePageViewModel.cs:132-208`）。
- **性能 MED**：改一个标签触发整页重载（`ItemCardActions.cs` → `ItemTagsChanged` → 活动页 `SearchAsync/LoadAsync` 整查重建）；搜索结果在 UI 线程逐条 `JsonSerializer.Deserialize` extra_json（最多 4 次/条）。
- **事件泄漏（MED）**：静态事件 `ItemTagsChanged`（`ItemCardActions.cs`）当前因订阅者均为单例 VM 未泄漏，但 Transient VM（如 `SettingsPageViewModel`）一旦订阅即每次导航泄漏；`SearchWidget.Results.CollectionChanged` 从未退订（`SearchWidget.xaml.cs:32`）。
- **改进**：搜索/筛选去抖 200–300ms；树构建移出 UI 线程，仅 `Roots.Add` 回 UI；标签改用增量更新；静态事件改 `CommunityToolkit.Mvvm.Messaging` 弱引用消息总线。

### 2.6 集成层 `StarMark.Integrations`
- **耦合（MED）**：见 1.2，Core/UI 直连具体类型；数据源接口 `IItemSource`（`Abstractions/IItemSource.cs`）本身设计良好、`SyncCoordinator` 构造注入 `IEnumerable<IItemSource>` 无需改。
- **硬编码**：`Everything 20000`（`EverythingInterop.cs:154`）、`Ditto 2000`（`DittoDatabaseReader.cs:67`）。
- **改进**：封装 `AddItemSource<T>()` DI 扩展或源类自注册 `[ItemSource]` 扫描；Core/UI 只依赖 `IItemSource`，去掉对 `Integrations.GitHub`/`SystemTray` 的直连。

### 2.7 基础设施 `App.xaml.cs`（609 行组合根）
- **DI 不一致（MED）**：`SettingsStore` 被到处 `new`（见下 6 处 + 更多），且 `App.Services.GetService(typeof(X)) as X` 弱类型服务定位器散点；Widget ViewModel 不进 DI。
- **改进**：`SettingsStore` 注册为单例并注入；用强类型 `GetService<T>()` 封装替换所有 `typeof(X) as X`；`AddItemSource<T>()` 削减样板。

## 四、性能优化优先级

- **HIGH**：①搜索/筛选去抖（每次按键全量 FTS+Everything）；②文件夹树构建移出 UI 线程（2000 条一次性建）。
- **MED**：写入/查询 N+1 与相关子查询；`COUNT(*)` 全索引扫；`WidgetStorage`/`SettingsStore`/`ExtraJson` 加缓存 + CJK 转义；库代码统一 `ConfigureAwait(false)`（当前靠 WinUI 无 SynchronizationContext 侥幸）；改标签增量更新；静态事件改消息总线。
- **LOW**：连接 PRAGMA 缓存；`async void` 改 `async Task`（ItemCardActions 8 处）；`ItemCardViewModel.TitleSegments` 缓存；`SearchWidget` 退订。

## 五、可扩展性评级与最高优先级重构

| 维度 | 评级 | 主要摩擦 |
|---|---|---|
| 新增热键动作 | 优秀 | 全新语义动作需补 `DisplayName` case |
| 新增数据源 | 良好 | 每源两行注册样板 |
| 新增 Widget | 中等 | 三处注册同步 + 存储类型分发 + 宿主特例 |
| 依赖注入 | 中等 | `SettingsStore` 到处 new、弱类型定位器 |
| 类型分发坏味道 | 多处 | `WidgetStorage:287`、WidgetWindow 特例、ItemType→图标 3 处重复 |
| 设置可扩展性 | 偏弱 | 四份镜像、无单一事实来源 |

**最值得先落地的两个重构（投入小、收益大）：**
1. **消除 `WidgetStorage.cs:287-289` 的「每组件一个具名集合 + 迁移 if/else」** → 改为组件自持 `IWidgetContentSerializer`。直接降低「新增有状态组件」的成本，并消除存储层类型分支。
2. **`SettingsStore` 入 DI + 引入「设置项描述符」/ 集中默认值** → 消除四份镜像与 `new SettingsStore()` 散点，所有未来设置的改动面从 4~5 文件降为 1 处。

## 六、重构执行顺序（按顺序，依赖从基础到上层、风险从低到高）

> 每完成一项须 `build 0错0警 + test 173/173` 后再进行下一项；每阶段结束时提交一个 `refactor(...)` commit（中文 conventional commit）。

### 阶段一：基础收敛（低风险，不改变行为）
- **T1** 修复 `SeedData.cs:70-71` 泄露开发者绝对路径 → 中性示例路径（不泄露机器结构）。
- **T2** 集中默认不透明度 `0.72`：`SettingsPageViewModel.cs:38,109`、`SettingsStore.cs:161` 改引用 `WidgetAppearance.DefaultOpacity`（已存在常量），消除字面量重复。
- **T3** 集中魔法常量：新增 `StarMark.Abstractions/AppConstants.cs`（或 `AppPaths`），收敛 `StarMark` 应用名、`2000/20000/100` 分页、`250` 去抖、`int.MaxValue`/30天 等；逐一替换并验证。

### 阶段二：存储与设置（中风险）
- **T4** `SettingsStore` 入 DI（注册单例 + 全仓 `new` 改注入）；引入「设置项描述符」统一默认值（消除四份镜像）。
- **T5** `WidgetStorage`/`SettingsStore` 增加内存缓存；`Save` 统一 `JavaScriptEncoder.UnsafeRelaxedJsonEscaping`（与 `BackupService` 一致）。

### 阶段三：数据层性能（中风险）
- **T6** 写入 N+1 与相关子查询优化（标签字典预取 + 批量 `VALUES`；列表两趟聚合替代每行子查询）。
- **T7** 健康度聚合查询替代 `int.MaxValue` 全表捞取（`SettingsPageViewModel.cs:142`）。
- **T8** `SearchAsync` 去除多余 `COUNT(*) FROM items_fts` 全索引扫描。

### 阶段四：UI/交互性能（中高风险）
- **T9** 搜索/筛选去抖（200–300ms）。
- **T10** 文件夹树构建移出 UI 线程（仅 `Roots.Add` 回 UI）。
- **T11** 改标签增量更新（消除整页重载）；静态事件 `ItemTagsChanged` 改 `CommunityToolkit.Mvvm.Messaging` 弱引用消息总线。
- **T12** 修复事件泄漏：`SearchWidget.Results.CollectionChanged` 退订；排查 Transient VM 订阅。

### 阶段五：扩展抽象（高风险，架构级）
- **T13** Widget 特性反射注册（`[Widget(Kind,Title,Glyph,DefaultSize)]` 合并三处注册）。
- **T14** `IWidgetContentSerializer` 消除 `WidgetStorage:287` 存储迁移 `if/else`。
- **T15** `IWidgetLifecycle` 下沉 `WidgetWindow` 中 Clock/QuickLaunch 特例。
- **T16** Core/UI 去耦 Integrations（只依赖 `IItemSource`）；`AddItemSource<T>()` 削减样板。
- **T17** 组合根 DI 强类型化（`GetService<T>()` 替换 `typeof(X) as X`）。
