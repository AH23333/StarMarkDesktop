## 2. 详细问题

### 🔴 F1 — 主界面不响应运行期系统主题翻转（跟随系统模式）

**现象**：主题设为「跟随系统」时，用户在 Windows 设置里切换深/浅色（或改强调色），组件窗口会跟着重挂材质与表面，但**主界面背景、状态点、来源按钮高亮、材质霜化配置停留在旧主题**，出现主界面与桌面组件一深一浅的割裂。

**根因**：全项目无任何 `UISettings.ColorValuesChanged` / 系统主题监听，主窗口也未订阅 `ActualThemeChanged`。

- 组件窗口有订阅：`WidgetWindow.xaml.cs:166` `RootBorder.ActualThemeChanged += (_, _) => RefreshAppearance();`
- 仅 `FolderTreePage.xaml.cs:31`、`TagsPage.xaml.cs:21` 两个页面为各自内容重绘订阅；**主窗口 `MainWindow` 无订阅**（全量检索 `ActualThemeChanged` 仅命中上述三处，无 `ColorValuesChanged`）。
- 主界面 `RootGrid.Background` 是**代码赋值**（`MainWindow.xaml.cs:127` → `MainWindowSurfaceBrush`），一旦代码赋值，XAML 里 `{ThemeResource}` 的自动跟随即被破坏；霜化主题的 `SystemBackdropConfiguration.Theme` 也只在 `ApplyBackdrop` 时按当时 `isDark` 设置（`WidgetAppearance.cs:104`），运行期不重发。

**对照 DeskBox（正确做法）**：`Services/ThemeService.cs` 构造即订阅 `_uiSettings.ColorValuesChanged += OnColorValuesChanged;`，回调里 200ms 去抖后 `RefreshAppearance()`，并维护 `_trackedWindows` 对所有窗口重下发主题（`ThemeService.cs:19-41`）。StarMark 缺这层「全局主题总线」。

**建议**：新增一个进程级主题监听（`UISettings.ColorValuesChanged`，注意回调在非 UI 线程，需 `DispatcherQueue.TryEnqueue`），在偏好为 `Default` 时统一调用 `MainWindow.RefreshAppearance()` 与 `WidgetManager.RefreshAppearanceAsync()/ApplyThemeToAllAsync()`；或直接给 `MainWindow` 根元素加 `ActualThemeChanged` 兜底重绘。

### 🔴 F2 — `ThemeBrush` 无法解析 WinUI 系统主题画笔，深色模式落到冻结主题

**现象**：运行期切换主题后，主界面来源按钮强调色/文字色、状态点、搜索高亮、组件置顶按钮等**代码设置的颜色不跟随新主题**，深色界面里出现浅色画笔（或反之）。

**根因**：`ThemeBrush.For/Resolve`（`Helpers/ThemeBrush.cs:19-53`）的解析口径只覆盖**应用自己重定义在 `Light`/`Default` 字典里的键**（`AppXxx`、`WidgetXxx`、两个 `Card*`）。对 WinUI **系统主题键**（`TextFillColor*`、`AccentFillColor*`、`SystemFillColor*` 等）：

1. `themeKey = dark ? "Default" : "Light"`（`:28`）——但 WinUI 注入的系统主题字典**深色键是 `Dark` 而非 `Default`**，于是 `FindInDict` 在深色分支查不到系统键；
2. 浅色分支 `themeKey="Light"` 能命中系统 `Light` 字典（所以浅色往往正常）；
3. 深色/未命中时落到 `app.TryGetValue(key)`（`:36`）——**取到的是「冻结的应用级主题」对应的画笔**，正是这套 helper 本该规避的值（其自身注释 `ThemeBrush.cs:9-13` 就写明了这个坑）。

结果是**浅色对、深色易错**的非对称行为。

**受影响调用点（示例，均传系统主题键）**：
- `MainWindow.xaml.cs:523-524`（`AccentFillColorDefaultBrush` / `TextFillColorSecondaryBrush`，来源按钮高亮）
- `MainWindow.xaml.cs:515-517`（`SystemFillColorSuccess/Caution`，状态点）
- `HighlightHelper.cs:43`（`SystemFillColorCautionBrush`，搜索关键词高亮）
- `WidgetWindow.xaml.cs:443`（`TextFillColorSecondaryBrush`，非置顶时图钉前景，无 `??` 兜底）
- `SettingsPage.xaml.cs` 的 `Brush()` 及代码构建行（同时叠加 F3）

**对照 DeskBox（正确实现）**：`Helpers/NeutralInteractionBrush.cs:48-87`：
- 先沿可视树向上取 host 作用域覆盖（`:54-64`）；
- 再按**元素 `ActualTheme`** 计算 `themeKey`，**深色用 `"Dark"`**（`:81-86`）读取 `Application.Current.Resources.ThemeDictionaries[themeKey]`（`:68-73`）——即从系统主题字典按当前主题取，不碰冻结的应用级资源。

**建议**：把 `ThemeBrush` 对齐 `NeutralInteractionBrush`：
1. 深色查找键补上 `"Dark"`（保留 `"Default"` 兼容自定义字典）；
2. 深色/未命中时改为读 `Application.Current.Resources.ThemeDictionaries["Light"/"Dark"]` 而非 `app.TryGetValue` 冻结兜底；
3. 或更彻底：把用到的少量系统键（`AppAccentBrush` 已有）在 `StarMarkTheme.xaml` 的 `Light`/`Default` 字典里各补一份等价画笔，保证所有代码解析键都命中自定义字典。

### 🟠 F3 — 设置页代码构建行硬编码 `ElementTheme.Default`

**现象**：应用内**手动**把主题设为浅色（或深色）而系统主题相反时，设置页里代码画出的分隔线、快捷键行配色用错主题；且运行期在设置页内切主题不重绘这些行。

**根因**：
- `SettingsPage.xaml.cs:315` 分隔线 `ThemeBrush.For(ElementTheme.Default, "WidgetDividerBrush")`；
- `SettingsPage.xaml.cs:459-460` `Brush(key,…) => ThemeBrush.For(ElementTheme.Default, key)`（快捷键行配色）。
- 传 `ElementTheme.Default` 时，`ThemeBrush.For`（`:21-22`）用 `ThemeManager.IsSystemDark()`（**系统主题快照**）决定深浅，与用户在应用内选的偏好无关。
- 这些行由 `BuildWidgetRows/BuildHotkeyRows` 仅在 `OnNavigatedTo` 与实例变更时构建（`SettingsPage.xaml.cs:170-172`），未订阅 `ActualThemeChanged`，主题切换后不重建。

**对照**：项目其它地方口径正确——弹窗用 `EffectiveTheme()`（`CenteredDialog.cs:322-331`、`WidgetAppearanceEditor.cs:838-847`，Default 才回退），组件/主窗口用 `ActualTheme`。**唯独设置页的 `Brush()`/分隔线写死 `Default`**。

**建议**：`SettingsPage` 的 `Brush()` 与 `:315` 改传 `this.ActualTheme`（或本页根元素 `ActualTheme`），并在页面加 `ActualThemeChanged` 触发这些代码行的重建（或改用 XAML `{ThemeResource}` 承载，避免代码解析）。

### 🟠 F4 — 关闭「主窗口材质」时主窗底色退化为纯黑/纯白

**现象**：设置里关掉「主窗口材质」(`MainWindowTranslucent=false`) 后，深色主题下主界面背景变成**纯黑 `#000000`**、浅色下纯白，比 WinUI 默认页面背景（深≈`#202020`）更硬、缺乏层次。

**根因**：`MainWindowSurfaceBrush`（`WidgetAppearance.cs:365-370`）非透明分支：
```
ThemeBrush.For(theme, "ApplicationPageBackgroundThemeBrush")
   ?? SurfaceBrush(theme, WidgetBackdropKind.None, 1.0);
```
`ApplicationPageBackgroundThemeBrush` 是系统主题键，受 F2 影响通常返回冻结色或 null；null 时落到 `SurfaceBrush(None, 1.0)`，而 None 分支返回 `dark ? Colors.Black : Colors.White`（`WidgetAppearance.cs:349-350`）——纯黑/纯白，非柔和的页面背景色。

**建议**：非材质态干脆**不要**用代码覆盖 `RootGrid.Background`，交回 XAML `{ThemeResource ApplicationPageBackgroundThemeBrush}`（`MainWindow.xaml:10` 本就是该资源）自动跟随；若必须代码赋值，`SurfaceBrush` 的 None 分支应返回主题页面背景色而非纯黑/纯白。

### 🟡 F5 — `ParseColorBrush` 对非法字符静默归零，错误色不回退

`WidgetAppearance.cs:378-397`：`HexDig` 对 `[0-9a-fA-F]` 之外的字符返回 0 而非使解析失败。故诸如 `"#GGHHII"`、含空格/中文的串会被「成功」解析成一个错误颜色，调用方（`WidgetWindow.xaml.cs:468/477`）以「非 null」判定为有效而采用，不再回退主题色。仅边界输入，但组件外观覆盖来自 JSON、可被手改/导入污染。
**建议**：`HexDig` 返回 `int?`（非法即 null），`ParseColorBrush` 任一字节非法即整体返回 null。

---

### 🟡 F6 — `ThemeManager.Apply` 运行期重复触发注定失败的应用级设置

`ThemeManager.cs:27-44`：每次 `Apply` 末尾都调 `ApplyAppLevelTheme(pref)`。而运行期窗口创建后 `Application.Current.RequestedTheme` 不可再设（`:41-42` 注释自陈会抛 `E_ILLEGAL_METHOD_CALL`，随即被 `catch` 吞掉）。功能无害，但属误导性/无谓异常开销。
**建议**：`Apply` 内不再调用 `ApplyAppLevelTheme`；应用级主题只在 `App` 启动、首窗创建前设一次（`App.xaml.cs:168` 已做）。

---

### ⚪ F7 — 主界面材质被不透明层遮盖（已知限制）

即便开启主窗口材质，顶栏 `TopBar`（`MainWindow.xaml:21` `LayerFillColorDefaultBrush`）、`NavigationView` 及各页面自带不透明背景会盖住霜化，导致「背景不透明度 / 材质浓度」两滑块对主界面观感影响很弱（代码注释在 `MainWindow.xaml.cs:119-127` 亦承认）。当前用「在原生材质上再压一层按不透明度调 Alpha 的主题色」缓解，但顶栏/导航不透明时仍透不出。
**建议**：材质模式开启时，同步把 `TopBar` / `NavigationView` / 页面容器背景调为透明或按不透明度联动（组件窗口因结构简单无此问题）。

## 3. 复核建议（回归用例）

1. **跟随系统实时翻转**：偏好=跟随系统 → Windows 设置切深↔浅 → 主界面背景、状态点、来源按钮、所有组件、当前打开的弹窗应同步；对照 F1/F2。
2. **强制主题 vs 系统主题**：系统设深色、应用内手动设浅色（及反向）→ 检查设置页分隔线/快捷键配色、来源按钮、搜索高亮、组件置顶图钉颜色是否正确；对照 F2/F3。
3. **六材质 × 两滑块**：逐一选亚克力薄/厚、云母/云母Alt、纯色Solid、不透明，拖「背景不透明度」「材质浓度」→ 主界面 + 组件均应即时变化且落盘重启后保持；重点验证云母下两滑块均生效（`CalculateMica` 已修，需回归确认）。
4. **主窗口材质开关**：关闭材质 → 主界面应为柔和页面色而非纯黑/纯白；对照 F4。
5. **弹窗主题**：在主界面切主题后即时打开确认框/外观编辑器 → 弹窗应跟随当前主题而非旧主题（当前 `ThemeManager.Apply` 时机正确，需回归）。

## §A 已核实缺陷

### 🔴 A1 — 设置文件写入非原子，损坏即静默清零
`Helpers/SettingsStore.cs:80-88`：`Save` 直接 `File.WriteAllText`，无「临时文件 + `File.Move` 原子替换」、无备份；`Load`（`:69-78`）`catch {}` 静默返回 null。写一半时崩溃/断电 → JSON 损坏 → 下次启动 `Load()` 返回 null → **所有偏好（主题/材质/热键/城市…）悄悄回到默认值**。且每个 getter/setter 都 `File.ReadAllText`+反序列化、`Load→改→Save` 全量读改写、无内存缓存与锁。
**建议**：写 `*.tmp` 后 `File.Replace/Move`；损坏时把原文件改名为 `.corrupt` 并写日志、从默认值重启；加进程内缓存 + 去抖异步落盘（对照 DeskBox `SettingsService` 的 lock+debounce）。

### 🔴 A2 — 材质取值在渲染/拖动热路径反复读盘
`Helpers/WidgetAppearance.cs:30-39`：`SnapEnabled()/Backdrop()/Opacity()/MaterialIntensity()/AccentColor()` 各自 `new SettingsStore().LoadX()`（每次磁盘 + JSON 反序列化）。这些被 `WidgetWindow.ApplyAppearanceCore`（一次 3+ 次读盘）与拖动 `PointerMoved` 磁吸判定高频调用，且回调在 UI 线程 → **拖动卡顿 / UI 线程磁盘 IO**。
**建议**：随 A1 一并加内存缓存（改设置时失效），或热路径缓存快照。

### 🔴 A3 — 深色主题下「来源」选中按钮白字压浅青强调色，几乎不可读
`MainWindow.xaml.cs:525,529`：选中按钮 `Foreground = new SolidColorBrush(Colors.White)`，而 `Background = AccentFillColorDefaultBrush`。深色模式强调色≈`#4CC2FF`（浅）→ **白字浅底、对比度崩坏**。（同一问题正落在 F2 的 `accent` 解析上：`ThemeBrush.For(...,"AccentFillColorDefaultBrush")` 走冻结兜底。）
**建议**：前景用 `TextOnAccentFillColorPrimaryBrush`，背景强调色按元素实际主题解析。

### 🟠 A4 — `Frame.Content` 被错误 cast 成 ViewModel，语言下拉启动后不回填
`MainWindow.xaml.cs:626`：`SyncLanguageCombo(ContentFrame?.Content as SearchPageViewModel)`——`Frame.Content` 是 `SearchPage`（Page），不是 VM，`as` 恒为 null。对照同文件正确写法 `:95` `ContentFrame.Content is SearchPage sp`。后果：启动/同步后搜索页「语言」选项与当前筛选不同步。
**建议**：`(ContentFrame.Content as SearchPage)?.ViewModel`。

### 🟠 A5 — 弹窗无真正模态/置顶，且高度未夹进工作区可被裁切
`Helpers/CenteredDialog.cs:370-373`：`SetTopmost(true)` 后**同一同步帧立即** `SetTopmost(false)`（注释称「拿到焦点后取消」实为顺序执行）→ owner 仍可交互、弹窗可被压到其它窗口之后（`RemoveDefaultWindowFrame` + `WS_EX_TOOLWINDOW` 下 Alt+Tab 也找不回）。

### D1 / D2 —— 浅色模式主界面黑底、组件恒深色

- 🔴 **[已核实] 根因：窗口根元素用 `ElementTheme.Default` 继承了"冻结的应用级主题"**：WinUI3 的 `Application.Current.RequestedTheme` 只能在首窗前设一次、随后冻结；而 `ThemeManager.Apply` 过去把 `Default` 直接下发给窗口根元素，`Default` 语义是**继承应用级主题**——于是运行期切主题时根元素不跟随，组件停在初始（多为深）主题，浅色下仅剩输入框按系统色发白。**已修**（`32b4d6a`）：`ThemeManager.Apply` 永不下发 `Default`，改由 `ResolveEffectiveTheme` 把 `Default` 就地在系统浅/深之间解析成**具体** `Light`/`Dark`。
- 🔴 **[已核实] 根因：代码侧画笔 `ThemeBrush.Resolve` 选错主题桶 + 深色桶键契约破裂**：第十五轮把深色桶键由 `"Default"` 改成 `"Dark"` 修好了 XAML，但内置 WinUI 画笔（generic.xaml）把深色桶命名为 `"Default"`——单认 `"Dark"` 反而**丢了内置画笔的深色解析**。且 `TagSelectedBrushConverter` 等以"冻结的应用级主题"判深浅，浅色误判为深。**已修**（`1525d98`）：`ThemeBrush.Resolve` 深色键序改为 `{"Dark","Default"}`（先取本调色板 `Dark`、回落内置 `Default`），浅色 `{"Light"}`；`IsAppDark()` 与选中标签转换器统一按**窗口根元素 `ActualTheme`** 判定。 `[v]` 浅色标签/卡片不再黑底需真机确认。

### D4 —— 组件"隐藏后再显示大多数时候点不出来"

- 🟡 **[读码定位] 根因：跨进程 owner 窗口上 `AppWindow.Show()/Hide()` 不可靠**：组件把窗口所有者设为 Explorer 的 `SHELLDLL_DefView`（桌面图标层，跨进程 ownership）。此类窗口仅调 `AppWindow.Show()` 常不触发真实 `SW_SHOW`，窗口不点亮；`IsVisible` 与真实可见态随之漂移，令"切换显隐"的分支判断也错。**对齐 DeskBox 修法**（`af53e0f`）：`Reveal()` 在 `AppWindow.Show()` 后补原生 `ShowWindow(hwnd, SW_SHOWNOACTIVATE)`；`HideTemporary()` 在 `AppWindow.Hide()` 前补 `ShowWindow(hwnd, SW_HIDE)`（同 `WidgetWindow` 内与 DeskBox `Win32Helper` 同款双保险）。 `[v]` 连开连关多轮需真机确认。

### D3 —— 材质与 DeskBox 不一致、纯色（Solid）失效

- 🔴 **[已核实] 根因：StarMark 的"纯色"其实是没去掉模糊的亚克力 + 双层 alpha**：`WidgetAppearance` 的 Solid 分支用 `DesktopAcrylicController` 并把 `LuminosityOpacity=0`，但 **acrylic 的采样模糊与颗粒始终存在**，`LuminosityOpacity` 只关掉亮度染色层、去不掉磨砂；再叠加内容表面 `SurfaceBrush(Solid)` 的第二道 alpha → 浅色下发灰、调不透明度也压不住。DeskBox 对照实锤：`WidgetWindowBase.Backdrop.ApplySolidColorBackdrop` 走 **`WinUIEx.TransparentTintBackdrop`**（一层 `CompositionColorBrush`，无任何模糊）挂到 `window.SystemBackdrop`，**先摘除** 云母/亚克力控制器，再 `DWMSBT_NONE`+`DisableAccentPolicy`；且为**单层**——背衬生效时内容 `BackgroundSurface` 保持透明（`if Solid && !IsSolidColorBackdropActive` 才刷表面）。**已修**（`1348720`）：引入 `WinUIEx 2.9.3`，Solid 分支 1:1 复刻——`TransparentTintBackdrop` 铺 `BuildContentSolidSurfaceColor(isDark, accent, surfaceOpacity)`，`DetachAcrylic/Mica` 后挂背衬；新增 `IsFlatSolidActive(window)`，`WidgetWindow.ApplyAppearanceCore` 在背衬生效时把 `RootBorder/DragBar` 置**透明**（消除双层），背衬未挂载时回落实色表面（不会变透明幽灵窗）；`ClearSolidBackdrop` 在切回亚克力/云母/不透明及释放时摘除背衬。 `[v]` 纯色最终观感/两个滑杆仍需真机微调与点验。

### D5 —— 布局应保存所有组件位置/大小/自定义配置；应用时"仅未修改者用当前主题"

- 🔴 **[已核实] 数据模型缺口**：`WidgetLayoutEntry` 原只含 `{Kind,Index,X,Y,Width,Height,Topmost}`，**不含**每实例自定义外观；`SaveCurrentLayout` 又**只快照可见窗口** → 隐藏组件丢失、个性化配置无法随布局还原。`WidgetInstanceConfig.Appearance`（材质/背景色/前景色/边框/圆角/文本缩放）正是"用户对组件的自定义配置"。**已修**（`cee1ed5`）：
  1. `WidgetLayoutEntry` 新增可空 `Appearance`（`WhenWritingNull`，旧布局零迁移）。
  2. `SaveCurrentLayout` 改为遍历**全部实例**：可见者读实时矩形、隐藏/失败者回退已持久化 config 值，并快照各自 `Appearance`。
  3. `ApplyLayoutCore` 逐实例还原 `inst.Appearance = entry.Appearance`：**null（未改过）→ 清覆盖、跟随当前全局主题；非 null（改过）→ 还原其自身外观**——即"只有未修改的组件才用当前设置主题"。
  4. 新增 `WidgetWindow.ApplyAppearance`（与 `ApplyBounds` 同理，把外观显式下发到窗口缓存的 `config` 并重挂材质，规避 `Load` 出多份对象图）；新建实例先落盘再 `ShowInternal`。附 `Layout_Entry_PersistsPerWidgetAppearanceOverride` 磁盘往返单测。
