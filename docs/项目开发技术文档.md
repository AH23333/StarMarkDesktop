## 一、可行性分析结论与技术验证

### 1.1 总体结论

**项目可行。** 原始可行性分析文档中的核心技术判断方向正确，本节通过外部资料对四项关键论断进行了独立验证，并发现一处原文档遗漏的关键约束（Everything 1.5 管道的完整性级别限制）。

### 1.2 关键技术论断验证

| 原文档论断 | 验证结论 | 证据 |
|-----------|---------|------|
| WinUI 3 在 2026 年 5 月实现性能跃迁（分配 -41%、函数调用 -45%、WinUI 代码耗时 -25%） | **确认属实** | 微软工程师 Beth Pan 在 microsoft-ui-xaml#11096 讨论中确认，File Explorer 与 Notepad 为基准测试应用。指标与原文档完全吻合 |
| Everything 1.5 命名管道 IPC 比 WM_COPYDATA 快约 5 倍 | **部分确认，存在遗漏** | Everything 1.5 SDK3 确实使用命名管道（`\\.\PIPE\Everything IPC`），默认 8 个管道服务器。但原文档未提及：**该管道 ACL 限制为 High-IL（高完整性级别）进程独占**。Medium-IL 进程连接会得到 `0xE0000002 IPC_PIPE_NOT_FOUND`。这是原可行性分析完全遗漏的硬约束 |
| FTS5 数值查询需外部表 JOIN 架构避免千倍性能下降 | **确认属实** | SQLite 官方文档与社区实践均证实，FTS5 倒排索引仅加速文本匹配；非文本条件触发全表扫描。外部内容表（External Content Table）是 SQLite 官方推荐模式 |
| SharpShell 可用于进程外 COM 服务器 Shell 扩展 | **确认可行，且方案已升级** | SharpShell 3.0.0 提供 .NET 8 兼容分支，结合 Native AOT + `EnableComHosting` 是当前推荐的现代化方案，不再依赖旧版 .NET Framework |

### 1.3 原文档遗漏的关键约束（必须重视）

**Everything 1.5 管道完整性级别限制**

Everything 1.5a 的命名管道安全描述符仅允许 High-IL 进程连接。StarMark 作为常规桌面应用默认运行在 Medium-IL，将无法直接连接 Everything 1.5 管道。可行解法见 [§6.2](#62-everything-15-管道完整性级别限制新增)。

这一约束不改变可行性结论，但**必须从架构设计阶段就纳入考量**，不能等到 Phase 1 集成时才发现。

### 2.2 核心数据流

**统一搜索数据流（最核心闭环）：**

```
用户键入关键词
    │
    ▼
SearchService.BuildQuery(keyword, filters)
    │
    ├─► ItemRepository.FtsSearch(keyword)        ← FTS5 MATCH 先缩小文本范围
    │       返回 rowid 列表（轻量阶段）
    │
    ├─► ItemRepository.HydrateFilter(rowids,    ← JOIN items 表做数值过滤
    │       filters.starsMin, filters.dateFrom)
    │       分页 + 完整字段 hydration
    │
    ├─► [可选] EverythingAdapter.Query(keyword) ← 本地文件实时补充
    │       通过查询队列串行化，避免 SDK 线程安全冲突
    │
    └─► MergeAndRank(ftsResults, fileResults)   ← 统一排序 + 去重标记
            │
            ▼
        UI: ObservableItemCollection 更新
```

**规则引擎数据流：**

```
[事件源] 文件系统变更 / GitHub 同步完成 / 定时器
    │
    ▼
RuleEngine.Evaluate(item)
    │
    ├─► ConditionMatcher.Match(item, rule.conditions)
    │       条件 DSL 评估（跨类型组合）
    │
    └─► 若匹配 → ActionExecutor.Execute(rule.actions)
            ├─ AddTagAction        打标签
            ├─ MoveFileAction      移动文件
            ├─ SetNoteAction       写入笔记
            └─ MarkDuplicateAction 标记疑似重复
```

```
┌──────────────────────────────────────┐
│  StarMark 主进程 (Medium-IL)          │
│  ├─ WinUI 3 UI                        │
│  ├─ 应用服务层                        │
│  ├─ 数据访问层                        │
│  └─ 集成适配层（除 Everything 1.5 外）│
└──────────────────────────────────────┘
        │                  │
        │ 命名管道          │ COM (进程外)
        ▼                  ▼
┌──────────────┐   ┌──────────────────────┐
│ Everything   │   │ ShellExtension      │
│ (独立进程)   │   │ (独立 COM 进程)      │
```

**关键决策：** 主进程不提权。Everything 1.5 的高 IL 要求通过独立方案解决（见 §6.2），主进程保持 Medium-IL 以避免触发 UAC 提示影响用户体验。

## 四、数据模型设计

### 4.1 统一条目主表

```sql
-- 统一条目主表：本地文件、书签、GitHub Star、剪贴板记录都是这张表的记录
CREATE TABLE items (
    id              INTEGER PRIMARY KEY,          -- 自增 rowid
    type            TEXT NOT NULL,                -- 'file' | 'bookmark' | 'github_star' | 'clipboard'
    source          TEXT NOT NULL,                -- 'filesystem' | 'chrome' | 'firefox' | 'github' | 'ditto'
    source_id       TEXT,                         -- 源内唯一标识（GitHub repo id、书签 URL、文件路径哈希）
    title           TEXT NOT NULL,
    subtitle        TEXT,                         -- 文件路径 / 书签域名 / repo 全名
    uri             TEXT,                         -- 可打开的统一标识（file:// / https:// / starmark://item/{id}）
    -- 文本索引字段（FTS5 外部内容表引用）
    search_text     TEXT,                         -- 拼接后的可搜索文本
    -- 数值过滤字段（不在 FTS5 中，放主表供 JOIN 过滤）
    stars_count     INTEGER,                      -- GitHub Star 数（仅 github_star 类型有值）
    file_size       INTEGER,                      -- 文件大小字节（仅 file 类型有值）
    created_at      INTEGER NOT NULL,             -- Unix 时间戳
    updated_at      INTEGER NOT NULL,
    synced_at       INTEGER,                       -- 最近一次与源同步的时间戳
    extra_json      TEXT,                          -- 扩展字段（语言、Topic、浏览器、剪贴板类型等）
);

-- 数值列索引（加速 JOIN 后的数值过滤）
CREATE INDEX idx_items_type_source   ON items(type, source);
CREATE INDEX idx_items_stars          ON items(stars_count) WHERE stars_count IS NOT NULL;
CREATE INDEX items_updated           ON items(updated_at);
CREATE UNIQUE INDEX idx_items_source ON items(source, source_id);
```

### 4.2 FTS5 外部内容表（关键架构）

```sql
-- FTS5 虚拟表：只索引文本，不存储数据副本
-- content='items' 指示 FTS5 不自己存文本，通过 rowid 回查 items 表
CREATE VIRTUAL TABLE items_fts USING fts5(
    title,
    search_text,
    content='items',
    content_rowid='id',
    tokenize='porter unicode61'      -- 支持英文词干 + Unicode 分词（兼容中文）
);

-- 同步触发器：items 表变更时自动维护 FTS5 索引
CREATE TRIGGER items_ai_fts AFTER INSERT ON items BEGIN
    INSERT INTO items_fts(rowid, title, search_text)
    VALUES (new.id, new.title, new.search_text);
END;

CREATE TRIGGER items_ad_fts AFTER DELETE ON items BEGIN
    INSERT INTO items_fts(items_fts, rowid, title, search_text)
    VALUES('delete', old.id, old.title, old.search_text);
END;

CREATE TRIGGER items_au_fts AFTER UPDATE ON items BEGIN
    INSERT INTO items_fts(items_fts, rowid, title, search_text)
    VALUES('delete', old.id, old.title, old.search_text);
    INSERT INTO items_fts(rowid, title, search_text)
    VALUES (new.id, new.title, new.search_text);
END;
```

### 4.3 标签与关联

```sql
CREATE TABLE tags (
    id          INTEGER PRIMARY KEY,
    name        TEXT NOT NULL UNIQUE,
    color       TEXT,                          -- 十六进制颜色（UI 显示用）
    created_at  INTEGER NOT NULL,
    extra_json  TEXT                           -- 描述、分组等
);

CREATE TABLE item_tags (
    item_id     INTEGER NOT NULL,
    tag_id      INTEGER NOT NULL,
    created_at  INTEGER NOT NULL,
    PRIMARY KEY (item_id, tag_id),
    FOREIGN KEY (item_id) REFERENCES items(id) ON DELETE CASCADE,
    FOREIGN KEY (tag_id)  REFERENCES tags(id)  ON DELETE CASCADE

CREATE INDEX idx_item_tags_tag ON item_tags(tag_id);
```

### 4.4 笔记

```sql
CREATE TABLE notes (

    item_id     INTEGER NOT NULL,
    content     TEXT NOT NULL,                  -- Markdown 文本
```

### 4.5 规则引擎

```sql
CREATE TABLE rules (
    id              INTEGER PRIMARY KEY,
    name            TEXT NOT NULL,
    enabled         INTEGER NOT NULL DEFAULT 1,  -- 0/1
    conditions_json TEXT NOT NULL,               -- 条件 DSL（见下）
    actions_json    TEXT NOT NULL,               -- 动作 DSL
```

### 4.6 查询模式（两阶段查询必须严格执行）

```sql
-- 阶段 1：FTS5 先缩小文本范围，获取 rowid 列表（命中倒排索引，毫秒级）
WITH fts_hits AS (
    SELECT rowid FROM items_fts WHERE items_fts MATCH @keyword
    ORDER BY rank  -- bm25 相关性排序
    LIMIT @page OFFSET @offset
)
-- 阶段 2：JOIN 主表做数值过滤 + 完整字段 hydration
SELECT i.*, GROUP_CONCAT(t.name) AS tag_names
FROM fts_hits f
JOIN items i ON i.id = f.rowid
LEFT JOIN item_tags it ON it.item_id = i.id
LEFT JOIN tags t ON t.id = it.tag_id
WHERE (@type_filter IS NULL OR i.type = @type_filter)
  AND (@stars_min IS NULL OR i.stars_count >= @stars_min)
  AND (@date_from IS NULL OR i.updated_at >= @date_from)
GROUP BY i.id;
```

## 六、关键工程约束与缓解方案

### 6.1 WinUI 3 性能优化未默认启用

**约束：** WinAppSDK 2.4.0 的性能优化需 opt-in，默认未启用。计划 3.0/4.0 才逐步默认。

**缓解：**
- 在 `Application.OnLaunched` 中通过 `RuntimeCompatibilityOptions` 选择性启用非破坏性优化项
- 不启用涉及控件样式破坏性改动的项
- 关注 WinAppSDK 3.0 发布节奏，发布后评估全量启用
- 性能关键页面（搜索结果列表）使用 `ItemsRepeater` 替代 `ListView`，手动控制虚拟化

### 6.2 Everything 1.5 管道完整性级别限制（新增）

**约束：** Everything 1.5a 命名管道 `\\.\PIPE\Everything IPC (1.5a)` 的 ACL 仅允许 High-IL 进程连接。Medium-IL 进程连接返回 `0xE0000002 IPC_PIPE_NOT_FOUND`。

**可选缓解方案（按推荐度排序）：**

1. **降级到 Everything 1.4 SDK + WM_COPYDATA（MVP 阶段推荐）**
   - 1.4 SDK 使用窗口消息 IPC，Medium-IL 即可工作
   - 性能略逊于 1.5 命名管道，但对文件名搜索场景已足够（毫秒级）
   - 丧失 1.5 的全文内容搜索能力（`content:` 查询）
   - **MVP 阶段采用此方案，标注为已知限制**

2. **独立 Elevated Helper 服务（Phase 4+）**
   - 单独的 Windows Service 以 LocalSystem 运行（High-IL）
   - 主进程通过命名管道与 Helper 通信（同机命名管道不受 IL 限制，可设 `CurrentUserOnly`）
   - Helper 转发 Everything 1.5 查询并返回结果
   - 优点：主进程不提权，UAC 不弹窗
   - 缺点：增加部署复杂度，需服务安装

3. **运行时检测 + 双后端切换**
   - 检测当前进程 IL（`CheckTokenMembership` / `GetTokenInformation`）
   - High-IL 直连 1.5；Medium-IL 降级 1.4
   - 用户可选「以管理员身份重启」启用 1.5

### 6.3 Everything SDK 线程安全限制

**约束：** SDK 一次只能处理一个查询，非线程安全。

**缓解：**
```csharp
public sealed class EverythingQueryQueue
{
    private readonly SemaphoreSlim _gate = new(1, 1);
    private CancellationTokenSource? _cts;

    public async Task<IReadOnlyList<FileItem>> QueryAsync(
        string query, SearchFilter filter, CancellationToken externalCt)
    {
        // 取消前一个查询
        _cts?.Cancel();
        _cts = CancellationTokenSource.CreateLinkedTokenSource(externalCt);
        var localCt = _cts.Token;

        await _gate.WaitAsync(localCt);
        try
        {
            // 动态选取最小必要请求标志
            var flags = ComputeMinimalFlags(filter);
            return EverythingInterop.Query(query, flags, localCt);
        }
        finally { _gate.Release(); }
    }

    private RequestFlags ComputeMinimalFlags(SearchFilter f)
    {
        var flags = RequestFlags.FileName | RequestFlags.Path;
        if (f.IncludeSize)   flags |= RequestFlags.Size;
        if (f.IncludeDate)   flags |= RequestFlags.DateModified;
        // 不需要的字段不请求，降低 IPC 负载
        return flags;
    }
}
```

### 6.4 FTS5 数值查询性能悬崖

**约束：** FTS5 倒排索引仅加速文本匹配；非文本条件触发全表扫描，性能下降超千倍。

**缓解：** 已在 [§4.6](#46-查询模式两阶段查询必须严格执行) 数据模型设计中通过两阶段查询架构解决。**此架构必须在 Phase 1 数据模型设计阶段就确定，不能等到性能问题出现后再重构。**

### 6.5 SQLite 同步查询阻塞 UI

**缓解：**
- 所有 SQLite 访问通过 `Microsoft.Data.Sqlite` 的异步 API
- 启用 WAL 模式：`PRAGMA journal_mode=WAL;` 读写不互锁
- 长查询在 `Task.Run` 中执行，UI 线程仅负责渲染
- 使用 `IAsyncEnumerable<Item>` 流式返回，分批更新 UI

### 6.6 Shell 扩展崩溃风险

**约束：** 进程内 COM 崩溃会导致 explorer.exe 重启。

**缓解：**
- 使用进程外 COM 服务器（SharpShell 3.0 + EnableComHosting）
- Shell 扩展崩溃不影响主进程，反之亦然
- Shell 扩展仅做最小工作：收集选中文件路径，通过命名管道发给主进程处理

### 6.7 跨源去重误判

**约束：** 同一资源可能从多源进入（GitHub repo 既是 Star 又有本地克隆）。

**缓解：** MVP 阶段不做自动合并，仅根据 URI 相似度标记「疑似重复」提示，由用户决定是否合并。

### 6.8 浏览器书签数据库锁定

**约束：** Chrome / Firefox 运行时其书签 SQLite 文件可能被锁定。

**缓解：**
- 以 `Mode=ReadWrite` + `Immutable=True` 之一尝试打开
- 捕获 `SQLITE_BUSY` 异常，回退到导出文件（HTML bookmarks）导入
- 提供「关闭浏览器后同步」的引导

### 8.1 项目结构

```
StarMarkDesktop/
├─ src/

│  ├─ StarMark.Core/                应用服务层（类库）
│  ├─ StarMark.Data/                数据访问层（类库）
│  ├─ StarMark.Integrations/        集成适配层（类库）
│  ├─ StarMark.SystemIntegration/   系统集成（类库）
│  ├─ StarMark.ShellExtension/      独立 COM 服务器项目
│  └─ StarMark.Abstractions/        接口与共享类型

│  ├─ StarMark.Core.Tests/

```

### 8.2 命名约定

- C# 项目：`StarMark.<Layer>`
- 命名空间：`StarMark.<Layer>.<Module>`
- 接口：`I` 前缀（`IItemSource`、`IViewer`、`IRuleAction`）
- 异步方法：`Async` 后缀（`FetchAsync`、`SearchAsync`）
- 私有字段：`_` 前缀（`_gate`、`_cts`）
- SQLite 表名：小写下划线（`items`、`item_tags`、`rule_runs`）
- SQLite 索引：`idx_<table>_<column>` 命名

### 8.3 异步与取消约定

- 所有跨层调用必须支持 `CancellationToken`
- 集成层查询必须可取消（用户键入新关键词时取消前一个）
- 使用 `CancellationTokenSource.CreateLinkedTokenSource` 组合外部取消与内部取消
- 禁止 `async void`（事件处理器除外），用 `async Task` + `FireAndForget` 扩展方法

### 8.4 错误处理约定

- 集成层不抛异常给应用层，返回 `Result<T>` 或捕获后记录日志
- UI 层使用 CommunityToolkit.Mvvm 的 `ObservableProperty` + 错误展示
- 所有外部依赖（Everything、浏览器数据库、GitHub API）必须有 `IsAvailable` 检测 + 降级路径

### 8.5 配置约定

- 应用配置：`%APPDATA%\StarMark\config.json`
- 数据库：`%APPDATA%\StarMark\starmark.db`
- 日志：`%APPDATA%\StarMark\logs\starmark.log`（按日轮转）
- 缓存：`%LOCALAPPDATA%\StarMark\cache\`
