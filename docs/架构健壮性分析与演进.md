分层架构（Abstractions / Data / Integrations / Core / UI）方向正确，无需推倒重构。本轮共发现并修复 **3 类数据完整性缺陷、2 类交互逻辑缺陷、1 类健壮性缺陷、24 个编译警告**；新增 **置顶（Pin）**、**EverythingToolbar 式快捷操作**、**搜索键盘导航** 三组能力。剩余风险已列入 §六 演进路线。

## 二、数据完整性（本轮最重要的重构）

### 2.1 已修复：同步覆盖用户状态（严重）

**问题：** `ItemRepository.UpsertOne` 的 `ON CONFLICT DO UPDATE SET` 包含 `hidden = excluded.hidden, notes = excluded.notes`。源适配器（GitHub/书签）构造的 Item 的 `Hidden=false`、`Notes=null`——**用户每次点同步，手动隐藏的条目会被取消隐藏，手写笔记会被清空**。此前隐藏功能在"同步后失效"的路径下必然复发。

**修复：** Upsert 前先按 `(source, source_id)` 读旧值合并进内存 Item（`hidden/pinned/notes`），再执行 UPSERT；`DO UPDATE SET` 排除这三个字段。副作用收益：`search_text` 重建时能带上用户笔记（旧代码用源侧 null notes 计算，笔记文本曾从 FTS 索引中丢失）。

### 2.2 已修复：标签同步清空重建

**问题：** Upsert 每次 `DELETE FROM item_tags WHERE item_id = @id` 再重建——用户手动 `AddTagAsync` 的标签在下一次同步时全部丢失（技术文档曾标注为"MVP 简化"）。

**决策：** 改为合并式（`INSERT OR IGNORE` 源侧标签，不再清空）。已知折衷：用户移除的标签若源侧仍声明，下次同步会复活。彻底方案需引入 `tags_source` 归属列（用户/源），列入 §六。

### 2.3 已新增：版本化列迁移

**问题：** `MigrationRunner` 只执行 `CREATE TABLE IF NOT EXISTS` 的 Schema.sql，**对已存在的库无法加列**，schema 演进会静默失败。

**实现：** `sync_state.schema_version` 版本检查 + 幂等 `ALTER TABLE items ADD COLUMN pinned`（v1→v2，`pragma_table_info` 判列存在）。Schema.sql 同步更新（新库直接建全列，迁移为 no-op）。后续列演进照此模式追加 vN。

### 2.4 已修复：FTS search_text 漂移

`SetNoteAsync` 重建 `search_text = title+desc+notes` 漏了 tags，与 Upsert 路径的口径（含 tags）不一致——同一行文本在两条路径下索引内容不同。已统一为含 tags 的口径。

## 四、新能力（对标决策）

### 4.1 EverythingToolbar 式快捷操作与键盘流

参考 [srwi/EverythingToolbar](https://github.com/srwi/EverythingToolbar)（Open path / Ctrl+Enter / 复制路径 / 键盘优先），落地：

- **卡片快捷操作**：右键菜单与操作栏新增 **复制链接/路径**（file:// 自动转本地路径）、**打开所在位置**（`explorer.exe /select`，仅本地文件条目显示）、**置顶切换**
- **键盘流**（搜索框内）：`↑/↓` 选择结果（卡片滚入视野，`ItemsRepeater.GetOrCreateElement().StartBringIntoView()`）→ `Enter` 打开选中 → `Ctrl+Enter` 打开所在位置 → `Esc` 清空回到浏览视图

### 4.2 置顶 Pin（"deskbox 自由度"的第一块拼图）

用户可把任意条目（书签/Star/文件/剪贴板）置顶，浏览视图（文件夹/标签/搜索的浏览排序）`ORDER BY pinned DESC` 稳定居首；置顶与隐藏、笔记同为**用户状态，同步永不覆盖**。这是"把桌面端当成可自由组织的快速取用盒子"方向的第一步；密度切换、分组置顶区、多级固定列入 §六。

## 五、架构分项评估

### 5.1 分层与依赖（✅ 健康）

依赖方向严格单向：UI → Core → (Data + Integrations) → Abstractions。UI 层无 SQL、Data 层无 UI 概念。`IItemRepository`/`IItemSource` 接口边界清晰，新源只需实现 `IItemSource` 并注册 DI——本轮加 pinned 未产生任何跨层渗透。

### 5.2 DI 生命周期（⚠️ 有一处刻意的不一致）

- 单例：`MainViewModel` / `SearchPageViewModel` / `FolderTreePageViewModel` / Repository / Sources —— 有意为之：跨页面保留搜索结果与树状态（第三轮修复确立）。
- 瞬态：`TagsPageViewModel` / `ActivityPageViewModel` / `HiddenPageViewModel` —— 每次导航重建，标签筛选态不跨导航保留（可通过导航参数恢复）。
- **风险点**：`TagsPage` 构造函数里 `App.Services.GetService<TagsPageViewModel>()` 对 transient 注册返回新实例，与 `?? new TagsPageViewModel(GetRepo())` 的兜底写法并存——语义等价但容易误读。后续统一为构造函数注入（见 §六）。

### 5.3 并发模型（✅ 基本健康，一处注意）

- 每次仓储调用独立 `SqliteConnection`（Microsoft.Data.Sqlite 默认连接池），WAL 模式下读写不互锁；`UpsertAsync` 内事务包裹。
- `SearchService` 并行发 FTS + 实时源查询，单源失败不拖垮整体（`SafeAwait`）。
- `SearchPageViewModel` 用 CTS 取消旧查询，防乱序回写。
- **注意**：Everything 查询队列 `SemaphoreSlim(1,1)` 串行化是 SDK 线程安全要求，勿移除。

### 5.4 性能（✅ 当前规模无瓶颈，两点预留）

- 实测 900+ 书签 / 900+ 标签 / 874 条目：FTS5 两阶段查询毫秒级；文件夹手风琴按需构建 + 每层 30 条起步。
- **预留 1**：TagsPage 标签云 ItemsRepeater 嵌在 ScrollViewer 内的 StackPanel 中，失去 viewport 虚拟化（900 个按钮一次性 realize）。当前体感可接受；若标签量翻倍，改为 repeater 直挂 ScrollViewer 或分页加载。
- **预留 2**：`GetAllAsync Limit=2000` 上限，超过后文件夹树静默截断。将来需要分页/游标。

### 5.5 失败模式（✅ 有兜底）

- 全局 `UnhandledException` + `AppDomain.UnhandledException` → StarLog 每日滚动文件。
- 同步协调器按源隔离失败（单个源不可用跳过）。
- 启动期 DB 初始化走 `Task.Run` 避开 UI 线程同步上下文死锁（第一轮修复，保持）。
- 解析器（书签 JSON、Everything CSV、Ditto DB）对损坏输入返回空集不中断。

### 5.6 代码质量

- 编译警告 **24 → 0**（CS8622 可空性 ×14、CS1998 ×6、CS4014 ×2、CS8321 ×2 全部清除；XAML 内残留 `{Binding}` 全部改 `x:Bind`，ItemsRepeater 内 `{Binding}` 会导致静默失效——第四轮已实证）。
- 回归测试 40/40（新增：`Upsert_PreservesUserState`、`SetPinned_BrowseSortsPinnedFirst`，并按新契约更新标签合并断言）。

## 六、演进路线（按优先级）

1. **标签归属列** `item_tags.origin(user|source)`——根治"用户移除的标签被同步复活"（§2.2 折衷）。
2. **ViewModel 构造注入统一**——`TagsPage` 等改为 Ctor 注入，删掉 ServiceLocator 兜底（§5.2）。
3. **deskbox 自由度第二批**：置顶分组区（文件夹页顶部独立"📌 已固定"区）、条目密度切换（紧凑/舒适）、置顶排序手动微调。
4. **EverythingToolbar 对齐第二批**：卡片右键直达 Windows 原生菜单（`ShowContextMenuAsync`）、结果数量可配、无鼠标全键盘工作流补完（标签/笔记的快捷编辑键）。
5. **Everything 索引进库**：Fetch 子集落库，让本地文件参与文件夹树/标签/置顶。
6. **标签云虚拟化**（§5.4 预留 1）与 `GetAllAsync` 游标化（§5.4 预留 2）。
