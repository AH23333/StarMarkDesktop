## 一、P0 —— 静默数据/功能损坏（优先）

### [x] R-P0-1 ｜ CJK 搜索被"改随记 / 加删标签"静默破坏
- 定位：`src/StarMark.Data/ItemRepository.cs`
  - `SetNoteAsync :283-290`（用纯 SQL 重建 `search_text = title || ' ' || desc || ' ' || @content || ' ' || tags`）
  - `AddTagAsync :212-249` / `RemoveTagAsync :252-264`（只动 `tags`/`item_tags`，**从不**重建 `search_text`）
- 根因：FTS 外部内容表以 `search_text` 为索引源；`search_text` 必须经 `CjkTokenizer.ExpandForIndex` 预展开（单字 + 相邻二元组），`unicode61` 才可按子串召回。上述路径写入的是**未展开原文**（且 `title` 列本身也是原文）→ 一条中文随记改过笔记或加过标签后，中文检索命中丢失。
- 修法：把 `search_text` 的重建从 SQL 上移到 C#——统一构造 `ExpandForIndex( 拼接(title, description, note, 各 tag) )`，`SetNote/AddTag/RemoveTag`（及 sync/upsert 的 D3/D4 分叉）都走同一 `BuildSearchText(item)` 帮助方法，写回后再触发 FTS 同步。
- 验证：中文条目改笔记/加标签后，仍能按原中文词与子串搜到；对照 `SeedData` 里预展开的条目命中一致。

### [x] R-P0-2 ｜ Everything 自动下载后进程内永久不可用
- 定位：`src/StarMark.Integrations/Everything/EverythingInterop.cs :100`（`EnsureSdkLoaded` 开头 `if (_sdkLoadError is not null) return false;`），错误置位于 `:111/:117/:127`
- 根因：`_sdkLoadError` 一旦置位**全局再无复位点**（Grep 证实）。`EverythingSource` 下载/安装成功（`Queue :183` 重试 `EnsureSdkLoaded`）后因该短路恒 `false` → 不装/不加载，Everything 源直到**重启进程**才可用。
- 修法：SDK 加载成功路径显式 `_sdkLoadError = null;`；或改为每次重试图先前清除上一次错误。确保 `Everything_SetMax/QueryW` 成功后返回 `true`。
- 验证：删除 `Everything64.dll` → 启动触发自动下载 → 无需重启即可搜到本地文件。

### [x] R-P0-3 ｜ 设置写盘非原子 + 空 catch → 崩溃即静默清空全部设置
- 定位：`src/StarMark.UI/Helpers/SettingsStore.cs` `Save() :80-88`（直接 `File.WriteAllText`）、`Load() :69-78`（整段 `catch { }` 返回 null）
- 根因：写中途断电/崩溃截断 `settings.json` → 下次解析抛错被吞成 null → 所有 `LoadXxx` 回落默认（主题/材质/浓度/快捷键/城市/性能预算全丢）且无日志痕迹，"配置被清空"伪装成"首次运行"。
- 修法：`Save` 写 `settings.json.tmp` 再 `File.Replace`（原子替换）；`Load` 的 `catch(Exception ex){ StarLog.Error(...) }`，可选把坏文件改名 `.bad` 再回落默认。
- 验证：注入写中断（模拟）或损坏文件后，日志有痕、原坏文件保留，程序可用默认继续。

## 二、P1 —— 可用性 / 一致性失灵

### [x] R-P1-1 ｜ 材质浓度 NaN 穿透 → 面板 alpha 0 完全隐形
- 定位：`src/StarMark.UI/Helpers/WidgetMaterialVisualCalculator.cs :131`（opacity 仅 `Math.Clamp`）、对照 `:173-176 NormalizeMaterialIntensity`（含 `double.IsFinite`）
- 根因：`Math.Clamp(NaN,…)` 两比较皆 false → 返回 NaN；NaN 经 `Lerp` → `(byte)Math.Round(NaN*255)`＝0 → 面板不可见。
- 修法：opacity 也走 `double.IsFinite` 守卫（取不到有效值回落默认），与 intensity 一致。附带 M2：统一各材质（native wash / 实色 / Mica）alpha 上限口径。
- 验证：把 opacity 存成非法值（NaN/超界）后组件仍可见、无 0 alpha。

### [x] R-P1-2 ｜ 搜索组件 fire-and-forget 重入 → 结果双份
- 定位：`src/StarMark.UI/ViewModels/SearchWidgetViewModel.cs :90-105`（`Results.Clear()`→`await SearchAsync(…,None)`→`Add`），调用方 `:80 ToggleTag`/`:87 ClearTags` 为 `_ = RunSearchAsync()`；同型 `QuickLaunchWidgetViewModel.cs:112-144`
- 根因：无 `CancellationTokenSource`/无串行化，两次快速操作交叠 → 前一 `await` 未完后一进 `Clear→Add`，结果翻倍或错乱。
- 修法：`RunSearchAsync` 前取消并替换成员级 CTS，向下游传 `cts.Token`；或对搜索命令用 `AsyncRelayCommand(AllowConcurrentExecutions=false)` 且经命令入口调用（勿直调私有方法绕开串行）。
- 验证：连点标签/清空，结果数不翻倍、无残留旧结果。

### [x] R-P1-3 ｜ 深链进入的页面停止自动刷新
- 定位：`src/StarMark.UI/MainWindow.xaml.cs` `NavigateTo :396-402`（不写 `CurrentPageTag`；`:398 SelectedItem=null` 使 `:386` 守卫提前返回）；闸位在 `FolderTreePageViewModel.cs:94`、`SearchPageViewModel.cs:356`
- 根因：仅 `NavView_SelectionChanged :389` 写 `ViewModel.CurrentPageTag`，编程式 `NavigateTo` 不写 → "仅当前页刷新"闸位停旧值 → 该页不再响应数据变更，切走再回才恢复。
- 修法：`NavigateTo` 内同步 `ViewModel.CurrentPageTag = tag`。
- 验证：从设置/标签深链进目录页，外部改数据即时刷新。

### [x] R-P1-4 ｜ 弹窗恒按主窗显示器居中（跨屏跑错屏）
- 定位：`src/StarMark.UI/Helpers/ItemCardActions.cs :94 ResolveOwner(XamlRoot?) => App.MainWindow;`（忽略入参）、`CenteredDialog.cs:359 GetWorkArea(owner)`
- 根因：入参 `xamlRoot` 未使用 → 永远取主窗显示器；从其它屏组件打开的 EditNote/EditTags/Preview 弹回主屏。
- 修法：由 `xamlRoot` 解析发起 `Window`（`xamlRoot.Dispatcher` → 反查窗口/维护 XamlRoot→Window 映射），无可靠映射才回落主窗。
- 验证：副屏组件弹窗居中于副屏。
- **实现说明**：`WindowInterop` 新增弱引用 `XamlRoot→Window` 登记表（`TrackWindow`/`ResolveWindow`，窗口 `Closed` 自动摘除）；主窗与组件窗构造时各自登记；`ResolveOwner` 惰性按宿主 `Content.XamlRoot` 反查、未命中回退 `App.MainWindow`。未用 `xamlRoot.Dispatcher` 反查（无稳定 API），改维护显式映射。跨屏观感待实机回填 `[v]`。

### [x] R-P1-5 ｜ SMTC 初始化失败永久禁用全部音乐组件
- 定位：`src/StarMark.UI/Views/MusicWidget.xaml.cs :80-84`（`s_initialized = true; :82` 置于 `await s_media.InitializeAsync(); :83` **之前**，失败不回滚）
- 根因：初始化标志先置真；一次 SMTC 初始化异常后，本进程所有音乐组件被永久标记为"已初始化"而不再重试。
- 修法：`s_initialized = true;` 移到 `await` **成功之后**；失败保持 false 以便下次重试（可加退避）。
- 验证：模拟首次 SMTC 失败后，重开组件可再次尝试初始化。

### [x] R-P1-6 ｜ 播放刷新卡死导致组件永久冻结
- 定位：`src/StarMark.UI/Services/MediaSessionService.cs :461-499`（`RefreshCoreAsync` 用 `_refreshing` 闩，`:499 await TryGetMediaPropertiesAsync()` 无超时/无 token 且在闩内；finally `:478-481` 复位）
- 根因：某个播放器挂起 → `await` 不返回 → `finally` 不执行 → `_refreshing` 永真 → 组件不再刷新。另 `:238 AttachSession` 未包 try（对照 `:289` 已包）。
- 修法：给媒体属性读取加 `CancellationToken`/超时；闩的复位确保在超时路径也执行；`AttachSession` 补 try。
- 验证：挂起一个播放器后组件不永久冻结，超时后仍可刷新。
- **实现说明**：`TryGetMediaPropertiesAsync().AsTask().WaitAsync(MediaReadTimeout=3s)`，超时抛 `TimeoutException` 由 `ReadSnapshotAsync` 既有 catch 兜住 → `finally` 复位 `_refreshing`、下次事件重试；`RefreshCoreAsync` 入口补 `_disposed` 守卫；`AttachSession` 的订阅/退订各自 try/catch 记日志并先换引用。挂起/超时行为待实机回填 `[v]`。

### [x] R-P1-7 ｜ 背衬在窗口隐藏/失活时仍常亮
- 定位：`src/StarMark.UI/Helpers/WidgetAppearance.cs :103`（`state.Config.IsInputActive = true` 为唯一写入；`Config.State` 从不设）
- 根因：仅设 `IsInputActive`，未随可见性/激活态更新 `SystemBackdropConfiguration.State` → 隐藏/失焦时材质仍激活（耗电、观感异常）。另 B2：`:160-161` 在 `ok=false`（无控制器）时仍置 `SystemBackdrop=null`+`SetDwmSystemBackdropNone` → "实色表面"回落并非真不透明（alpha≤0.94）。
- 修法：随 `Activated/Deactivated/Visible` 更新 `Config.State`（Active/Inactive/Hidden）；无控制器时走真正不透明实色而非半透背衬。
- 验证：隐藏组件后系统材质停用；"不透明"档实测不透底。
- **实现说明**：核实 Windows App SDK 2.4.0 与 DeskBox 基线均**未**使用 `SystemBackdropConfiguration.State`/`BackdropState`（反射+基线双向证实）；基线以 `IsInputActive` 跟随 `Window.Activated` 驱动 Active/Inactive。据此改：每窗一次性挂 `Activated` 事件按 `!= Deactivated` 置 `IsInputActive`（隐藏近似为 Inactive），`Config` 与控制器同实例实时生效。B2 透明幽灵窗：`ok=false`/`solidOk=false` 分支补 `WindowInterop.ClearFullWindowFrame` 撤玻璃化、兑现真不透明兜底。失焦/隐藏观感与"不透明档"待实机回填 `[v]`。

### [x] R-P1-8 ｜ 结果去重按原始 Uri，file:// 与 file:/// 未归一
- 定位：`src/StarMark.Core/Search/SearchService.cs :78`（以原始 `Uri` 为去重键）；Everything 产 `file://`（2 斜杠）vs DB/SeedData `file:///`（3 斜杠）
- 根因：同一本地路径两来源表示不同 → 去重失败出现重复行。另 `:57-62` 在 `filter.HasTags` 时跳过实时源（S3，设计如此但 UI 无提示）。
- 修法：去重键改用 `UriNormalizer`（或 `LocalPath` 规范化）；标签筛选时若跳过实时源，UI 给出可见提示。
- 验证：同一路径经 Everything+DB 各一条时结果只一条。
- **实现说明**：新增 `CanonicalizeUri`——`file://` 走 `new Uri().LocalPath`（与 `FolderPathUtil`/`LauncherEx` 同法）折叠两斜杠差异，非文件 URI 原样返回，非法 URI 退回原串避免误合并；去重键改用它。补 `Dedup_FileUriFormDifference_CollapsesToOne` 回归（297/297 绿）。S3「跳过实时源的 UI 提示」属产品设计，未纳入本修，保留备查。多来源真实合流待实机回填 `[v]`。

### [x] R-P1-9 ｜ 非 DPI 缩放下列可拖区错位
- 定位：`src/StarMark.UI/MainWindow.xaml.cs :312-316 ApplyDragRects`（`SetDragRectangles` 取物理像素，却混用 `AppWindow.Size.Width`(物理) 与 `TopBar.ActualHeight`/`TopBarButtons.ActualWidth`(DIP)）
- 根因：物理像素与 DIP 混算，非 100% 缩放下拖拽条高度/按钮避让区错位。
- 修法：统一换算（`ActualHeight` 等乘 `RasterizationScale`），或在同一坐标系内计算。
- 验证：150% 缩放下标题栏可拖、按钮可点不串位。
- **实现说明**：`ApplyDragRects` 取 `WindowInterop.GetScale(this)`（96=DPI 比），把 `TopBar.ActualHeight`/`TopBarButtons.ActualWidth`/常量 padding 一律 `× scale` 取整后再与物理 `AppWindow.Size.Width` 相减。已随 `SizeChanged` 重算，故 DPI 变化即时生效。非 100% 缩放下观感待实机回填 `[v]`。

### [~] R-P1-10 ｜ 配置缺版本字段 + 每 getter 重读盘
- 定位：`SettingsStore.cs SettingsData :28-65`（无 `Version`）；每个 `LoadXxx` 调 `Load()` 全文重读+反序列化；`App.xaml.cs :94/:151/:168/:206` new 了四个独立实例
- 根因：字段级默认可前向兼容"新增字段"，但无整档版本 → 无法在语义/枚举重排时迁移或拒绝更新版写回；每 getter 重读放大 IO（开设置页≈12 次读+解析）。
- 修法：加 `int? Version`；`Load()` 进程内缓存快照（`Save` 失效）；`SettingsStore` 注册为单一 DI 单例注入。
- 验证：磁盘 IO 计数下降；旧版坏枚举被版本迁移兜住。

### [x] R-P1-11 ｜ `SetWindowRgn` 返回值被丢弃致 GDI 区域句柄泄漏
- 定位：`src/StarMark.UI/Helpers/WindowInterop.cs :237-238`（`if (hrgn != Zero) SetWindowRgn(hwnd, hrgn, true);` 忽略返回）
- 根因：成功时窗口接管并释放旧区域；**失败时**调用方仍须 `DeleteObject(hrgn)`，当前丢弃返回 → 失败路径 GDI 句柄泄漏。
- 修法：判 `SetWindowRgn` 返回（`0`/失败即 `DeleteObject(hrgn)`）；或按 Win32 约定失败时释放。
- 验证：反复切圆角/无泄漏（任务管理器 GDI 对象数稳定）。
